# 用户体验和使用逻辑问题分析

## 🤔 发现的UX问题

### 问题1: 自动同步的"魔法"让用户困惑 ⚠️ **严重**

**场景重现：**

```
用户A: 我在专攻页面修改了考试时间为11月15日
用户A: （切换到时间线页面）咦？怎么多了3个日程？
用户A: 这些日程是谁创建的？我没有点"添加日程"啊！
用户A: 那个"⟳"图标是什么意思？
```

**问题本质：**

- ❌ 没有明确告知用户"修改考试会自动生成日程"
- ❌ 自动生成是"隐式"的，用户没有预期
- ❌ ⟳ 图标不够直观，很多用户不知道是同步的意思

**改进建议：**

#### 方案A：添加明确的提示（推荐）

在专攻考试历史保存时，弹出提示：

```vue
<Modal v-model:open="syncNoticeOpen" title="提示">
  <p>检测到考试时间已更新，系统将自动为以下研究室同步日程：</p>
  <ul>
    <li>田中研究室：笔试、面试、放榜（3个事件）</li>
    <li>佐藤研究室：笔试、面试、放榜（3个事件）</li>
  </ul>
  <p>你可以在时间线页面查看或手动修改这些日程。</p>
  <Checkbox v-model:checked="dontShowAgain">不再提示</Checkbox>
</Modal>
```

#### 方案B：改进首次引导

在用户首次看到自动生成的日程时：

```vue
<Alert
  v-if="hasAutoSyncedEvents && !dismissed"
  type="info"
  closable
  @close="dismissAutoSyncGuide"
>
  <template #message>
    <strong>💡 智能日程同步</strong>
  </template>
  <template #description>
    带有 <Tag color="blue">⟳ 自动</Tag> 标记的日程来自专攻考试历史。
    修改专攻考试时间后，这些日程会自动更新。
    你也可以手动编辑它们，修改后不会被覆盖。
  </template>
</Alert>
```

#### 方案C：改进图标和文案

```vue
<!-- 当前 -->
<span class="sync-badge" title="自动同步自专攻考试历史">⟳</span>

<!-- 改进后 -->
<Tag color="blue" size="small">
  <SyncOutlined /> 自动
</Tag>
```

### 问题2: 用户不知道什么时候会触发自动同步 ⚠️ **中等**

**用户困惑：**

```
用户: 我在研究室A修改了日程，会影响研究室B吗？
用户: 我手动创建的日程会被自动同步覆盖吗？
用户: 如果我不想要自动同步，怎么关闭？
```

**问题本质：**

- 同步规则不透明
- 用户不清楚"主数据"和"派生数据"的关系

**改进建议：**

在研究室详情页添加说明卡片：

```vue
<Card title="📅 日程来源说明" class="timeline-help">
  <Space direction="vertical">
    <div>
      <Tag color="blue">⟳ 自动同步</Tag>
      来自专攻考试历史，修改专攻考试时间后会自动更新
    </div>
    <div>
      <Tag color="green">✓ 手动创建</Tag>
      你自己添加的日程，不会被自动同步覆盖
    </div>
    <div>
      <Switch v-model:checked="lab.timeline.autoSyncExams" />
      关闭自动同步（已有的日程保留，新的不再自动创建）
    </div>
  </Space>
</Card>
```

### 问题3: "覆盖"和"替换"的概念难以理解 ⚠️ **中等**

**当前逻辑：**

```typescript
event.replaces = 'major:abc:exam:xyz:written'; // 替换自动生成的事件
timeline.hiddenSources = ['major:abc:exam:xyz:written']; // 隐藏来源
```

**用户困惑：**

```
用户: 什么是"隐藏来源"？
用户: 我点了"恢复来源日程"，原来的日程去哪了？
用户: 为什么有两个日程显示同一个考试？
```

**问题本质：**

- "replaces" 和 "hiddenSources" 是技术实现细节
- 用户不需要理解这些概念
- 应该用更直观的方式表达

**改进建议：**

#### 方案A：简化为"锁定"概念

```vue
<!-- 当前：自动生成的事件 -->
<button @click="editEvent(event)">
  ⟳ 2024年笔试
</button>

<!-- 改进后：添加锁定状态 -->
<button @click="editEvent(event)">
  <LockOutlined v-if="event.userLocked" />
  <SyncOutlined v-else />
  2024年笔试
</button>

<!-- 编辑对话框中 -->
<Alert type="info">
  这是自动同步的日程。
  <a @click="lockEvent">锁定此日程</a> 后，将不再随专攻考试时间更新。
</Alert>
```

#### 方案B：改进"恢复来源"的文案

```vue
<!-- 当前 -->
<Button @click="restoreSources(lab.id)">恢复来源日程</Button>

<!-- 改进后 -->
<Popconfirm
  title="恢复自动同步？"
  description="将删除你的手动修改，恢复为专攻考试历史的时间"
  @confirm="restoreSources(lab.id)"
>
  <Button>恢复专攻设置</Button>
</Popconfirm>
```

### 问题4: 分析历史的价值不明显 ⚠️ **轻微**

**用户困惑：**

```
用户: "分析历史"是什么？
用户: 这些记录有什么用？
用户: 为什么要显示"p.3"？
```

**问题本质：**

- 功能名称不够直观
- 没有说明这个功能解决什么问题

**改进建议：**

```vue
<!-- 当前 -->
<h3>
  <ExplorerIcon name="clock" />分析历史
</h3>
<p>记录募集要项分析采纳的来源文件与时间</p>

<!-- 改进后 -->
<h3>
  <ExplorerIcon name="clock" />数据来源追溯
</h3>
<p>
  显示每个数据从哪份募集要项提取，方便核对和更新。
  <Tooltip title="例如：出愿时间来自2025年度募集要项第3页">
    <QuestionCircleOutlined />
  </Tooltip>
</p>
```

并且添加一个用例说明：

```vue
<Empty v-if="!history.length">
  <template #description>
    <Space direction="vertical">
      <div>💡 为什么需要追溯来源？</div>
      <div style="text-align: left; max-width: 400px;">
        <ul>
          <li>对比新旧募集要项时，快速找到变化部分</li>
          <li>核对数据准确性时，直接跳转到原文档</li>
          <li>多人协作时，知道数据是谁、什么时候添加的</li>
        </ul>
      </div>
    </Space>
  </template>
</Empty>
```

### 问题5: 版本冲突提示不友好 ⚠️ **中等**

**当前提示：**

```
工作区已在其他页面更新，请刷新后重试。(409)
```

**用户困惑：**

```
用户: 什么叫"工作区"？
用户: 我修改了什么被覆盖了吗？
用户: 刷新后我的修改会丢失吗？
```

**改进建议：**

```vue
<Modal v-model:open="conflictModalOpen" title="⚠️ 数据冲突" :closable="false">
  <Alert type="warning" show-icon>
    <template #message>其他标签页修改了相同的数据</template>
    <template #description>
      <p>你正在编辑：<strong>{{ editingItem }}</strong></p>
      <p>但它已在另一个标签页被修改。</p>
      <p style="margin-top: 16px;">你可以：</p>
      <ul>
        <li><strong>刷新后重新编辑</strong>（推荐）- 你的修改会丢失</li>
        <li><strong>强制保存</strong> - 会覆盖另一个标签页的修改</li>
      </ul>
    </template>
  </Alert>

  <template #footer>
    <Button @click="reloadPage">刷新页面</Button>
    <Button type="primary" danger @click="forceSave">
      强制保存（不推荐）
    </Button>
  </template>
</Modal>
```

### 问题6: 智能导入和自动同步的关系不清晰 ⚠️ **中等**

**场景：**

```
用户在募集要项分析中：
1. 采纳了出愿时间（11月1-30日）
2. 选择"创建材料待办"和"创建时间待办"
3. 保存

用户切换到时间线页面，发现：
- 有"出愿开始"待办（11月1日）✓
- 有"出愿截止"待办（11月30日）✓
- 还有"出愿"日程（11月1-30日）⟳

用户: 为什么有重复？待办和日程有什么区别？
```

**问题本质：**

- 智能导入创建"待办"
- 自动同步创建"日程"
- 两者都来自同一个数据源，看起来重复

**改进建议：**

#### 方案A：在分析采纳时提示

```vue
<Checkbox v-model:checked="createTodos">
  创建时间待办（推荐用于追踪任务进度）
</Checkbox>

<Alert type="info" style="margin-top: 8px;">
  <div>另外，系统还会自动在时间线创建日程事件（用于甘特图展示）。</div>
  <div>待办和日程可以共存，分别用于不同场景。</div>
</Alert>
```

#### 方案B：提供合并选项

```vue
<Radio.Group v-model:value="importMode">
  <Radio value="todos">只创建待办任务</Radio>
  <Radio value="timeline">只在时间线显示（不创建待办）</Radio>
  <Radio value="both">两者都创建（推荐）</Radio>
</Radio.Group>
```

### 问题7: 日程编辑对话框缺少来源信息 ⚠️ **轻微**

**当前状态：** 用户点击编辑一个自动同步的日程，看到普通的编辑表单，不知道这是自动生成的。

**改进建议：**

```vue
<template #header>
  <Space>
    <span>编辑日程</span>
    <Tag v-if="event.autoGenerated" color="blue">
      <SyncOutlined /> 自动同步
    </Tag>
  </Space>
</template>

<!-- 在表单顶部添加提示 -->
<Alert v-if="event.autoGenerated" type="info" closable>
  <template #message>此日程自动同步自专攻考试历史</template>
  <template #description>
    <div>来源：{{ getSourceDescription(event.sourceId) }}</div>
    <div>
      修改后将不再自动更新。
      <a @click="goToSource">前往专攻页面修改原始数据</a>
    </div>
  </template>
</Alert>
```

### 问题8: 批量操作的缺失 ⚠️ **中等**

**场景：**

```
用户: 我标记了10个"想考"的研究室
用户: 每个研究室都要手动点"添加日程"吗？
用户: 能不能一键为所有想考的研究室创建日程？
```

**当前问题：**

- 专攻考试变更后，自动同步只针对单个研究室
- 如果用户关闭了自动同步，需要一个个手动创建

**改进建议：**

在"修考之路"页面添加批量操作：

```vue
<div class="batch-actions">
  <Dropdown>
    <Button>
      批量操作 <DownOutlined />
    </Button>
    <template #overlay>
      <Menu>
        <Menu.Item key="sync-all" @click="syncAllWantApply">
          <SyncOutlined /> 同步所有想考研究室的日程
        </Menu.Item>
        <Menu.Item key="create-todos" @click="createTodosForAll">
          <CheckSquareOutlined /> 为所有研究室创建材料待办
        </Menu.Item>
        <Menu.Divider />
        <Menu.Item key="export" @click="exportSelected">
          <ExportOutlined /> 导出选中的研究室
        </Menu.Item>
      </Menu>
    </template>
  </Dropdown>
</div>
```

## 🎯 优先级总结

### 🔴 高优先级（影响核心理解）

1. **问题1：自动同步的"魔法"** - 需要明确提示
2. **问题2：不知道何时触发** - 需要添加说明和开关
3. **问题5：版本冲突提示** - 需要改进文案

### 🟡 中优先级（影响使用流畅度）

4. **问题3："覆盖"概念难懂** - 简化为"锁定"
5. **问题6：智能导入和同步的关系** - 添加说明
6. **问题8：批量操作缺失** - 添加批量同步功能

### 🟢 低优先级（锦上添花）

7. **问题4：分析历史价值不明显** - 改进文案
8. **问题7：编辑对话框缺少信息** - 添加来源提示

## 💡 总结

**核心问题：** 功能很强大，但逻辑不够显性化

用户遇到的最大困惑是：

1. ❌ 不知道什么是自动生成的
2. ❌ 不知道修改考试会生成日程
3. ❌ 不知道自动生成的日程能不能改
4. ❌ 不知道怎么关闭自动同步

**建议：**

- 最小改进（1-2小时）：添加说明文案和提示
- 推荐改进（5-6小时）：完整的引导系统
- 理想状态（10小时）：全套批量操作和智能提示

**优先做阶段1的最小改进，就能解决80%的用户困惑！**
