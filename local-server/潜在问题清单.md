## ⚠️ 需要注意的问题

### 1. 数据迁移触发时机（已关闭）

### 2. 大数据量下的同步性能 ⚠️ 轻微

**问题描述：** 如果一个专攻有50+年的考试历史，`syncExamsToTimeline` 可能生成 150+ 个事件。

**当前限制：**

```javascript
// timeline-fields.mjs:24
value.events.length > 200;
```

**风险：**

- 超过200个事件会验证失败
- 用户无法保存

**解决方案1（推荐）：** 只同步最近5年的考试历史

```javascript
// 在 syncExamsToTimeline 中添加过滤
const recentYears = 5;
const currentYear = new Date().getFullYear();
const recentExams = examHistory.filter(
  (exam) => parseInt(exam.year) >= currentYear - recentYears,
);
```

**解决方案2：** 增加日程上限到 500

```javascript
// timeline-fields.mjs:24
value.events.length > 500;
```

**建议：** 采用解决方案1

### 3. 考试历史ID变更导致的孤立日程 ⚠️ 轻微

**问题描述：** 如果用户删除并重新创建同一年的考试记录，sourceId 会变化，导致旧日程变成孤立事件。

**示例：**

```javascript
// 原考试记录
{ id: 'exam-abc', year: '2024', writtenDate: '2024-11-15' }
// 生成日程
{ sourceId: 'major:m1:exam:exam-abc:written' }

// 用户删除后重建
{ id: 'exam-xyz', year: '2024', writtenDate: '2024-11-15' }
// 新日程
{ sourceId: 'major:m1:exam:exam-xyz:written' }

// 结果：旧日程 (exam-abc) 不会被清理
```

**当前处理：** `syncExamsToTimeline` 第223-229行会清理无效的自动生成事件，但只匹配考试ID前缀。

**风险：** 非常低（用户很少删除后重建）

**改进建议：** 添加"年份+类型"的额外匹配逻辑，确保同一年的同类事件只保留一个。

### 5. 分析历史的页码提取可能不准确 ⚠️ 轻微

**问题描述：** 在 `analysis-service.mjs:1069` 我们提取页码：

```javascript
const evidence = proposal.fields[key]?.evidence || [];
const pages = [...new Set(evidence.map((e) => e.page).filter(Boolean))];
```

但如果 `evidence` 结构不是预期的，`e.page` 可能是 `undefined`。

**建议：** 添加更严格的验证：

```javascript
const pages = [
  ...new Set(
    (evidence || [])
      .filter((e) => e && typeof e.page === 'number')
      .map((e) => e.page),
  ),
];
```

### 补丁2：在snapshot中自动应用迁移

```javascript
// 在 server.mjs 的 snapshot 函数中：
const snapshot = () => {
  const row = db.prepare('SELECT * FROM workspace_data WHERE id = 1').get();
  if (!row) {
    return {
      initialized: false,
      revision: 0,
      data: structuredClone(EMPTY_DATA),
      workspace,
    };
  }

  let data = JSON.parse(row.data);

  // 自动应用迁移（只在内存中，不写入数据库）
  const needsMigration =
    !data.labs?.[0]?.timeline?.version && data.labs?.length > 0;

  if (needsMigration) {
    data = applyMigrations(data);
  }

  return {
    initialized: true,
    revision: row.revision,
    data,
    workspace,
  };
};
```
