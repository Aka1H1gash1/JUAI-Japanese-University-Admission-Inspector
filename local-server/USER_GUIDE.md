# JapanGrad 本地工作台

适用于 Apple Silicon Mac。软件包内含运行时，不需要安装 Node.js、Java、数据库或开发依赖。

## 启动

解压 v1.2 便携包后，Windows 双击 `JUAI.exe`，macOS 双击 `JUAI.app`。JUAI 会在后台启动内置的本地数据服务，并优先使用现有 Google Chrome 打开进入页。不需要安装 Node.js、Electron 或数据库。再次点击 JUAI 只会重新打开页面。需要停止后台服务时，在「设置 → 手机访问」点击「完全退出 JUAI」。

手机与电脑位于同一 Wi-Fi 时，可在同一设置页临时开启手机访问，再把生成的带密钥链接发送到自己手机。手机只是访问电脑上的数据；电脑必须保持开机且 JUAI 保持运行。手机入口默认关闭，每次启动使用新密钥。

进入页提供校园意象画面、轻缓入场与景深位移，可点击「暂停动态」。系统设置了减少动态效果时自动显示静态画面；浅色 / 深色随系统切换。图片和开放字体随软件包本地提供。生成的校园画面仅为视觉意象，不代表具体大学的实景。

系统默认浏览器即可使用。首次打开未签名的软件时，macOS 可能要求在系统设置「隐私与安全性」中允许打开；当前包是本地开发试用包，尚未签名、公证。

## 界面布局

导航只保留主要功能和当前路径，不再展示「我的大学」快捷列表、侧栏底部统计与位置卡片。页头已移除全局 AI 助手和主题按钮；工作区位置仍可从页脚查看。大学清单、修考之路与特殊项目页移除了重复的统计和提示条，修考之路使用全宽主区域，对比年份在对比窗口内选择。外部 Agent 授权统一从 AI 管理的高级设置进入。

## 资料存在哪里

默认工作区为 `~/Documents/JapanGradWorkspace`（用户文稿文件夹）。软件目录与资料目录独立：移动或删除软件不会删除资料。

```text
JapanGradWorkspace/
├── workspace.db                    # 大学、专攻、考试记录、老师、资料索引和邮件
├── workspace.json                  # 工作区版本信息
├── university-logos/                # 上传的校徽原图片
├── majors/<专攻 ID>/
│   ├── guidelines/<招生年度>/       # 募集要项原文件
│   ├── question/<考试年份>/         # 过去问原文件
│   └── answer/<考试年份>/           # 关联答案原文件
├── professors/<老师 ID>/paper/<发表年份>/
└── .trash/                         # 在界面移除的 PDF，可恢复原文件
```

上传会复制原文件。文件保存在本地，可在工作台内阅读 PDF、TXT / MD 和 DOCX 提取文字，也可下载原文件或直接从文件夹查看。邮件正文、阅读笔记和位置记录保存在 SQLite 中。

## 使用

### 阅读与笔记

点击募集要项、过去问或老师论文卡片，直接进入独立阅读页；卡片右上角「资料与编辑」仍可维护标题、作者等信息。顶部返回按钮回到所属专攻或老师，主页图标进入申请总览。

- PDF：目录 / 页面缩略图、页码跳转、适合宽度 / 整页 / 指定比例、旋转与专注阅读。长文档按需呈现页面；工具栏记录阅读位置，再次打开可继续阅读。
- 搜索：左侧搜索，或使用 Ctrl / Command + F。点击结果跳页并高亮，最多展示前 200 处匹配；扫描页没有文字层时无法划词或全文搜索，会明确提示，仍可写普通笔记。
- 原文高亮：在同一页选择文字后点击「高亮」，会保存原文和位置。需要写想法时点「笔记」，原文摘录会带入右侧。高亮颜色可在编辑笔记时调整。
- 笔记：可以写原文批注或全文笔记，按页码 / 最近编辑排序，搜索标题、内容和摘录。点击摘录回原文。草稿自动暂存在当前浏览器，点击「保存笔记」或 Ctrl / Command + Enter 后写入本地工作区；保存失败会保留草稿。
- 导出：右下角「导出笔记」下载 Markdown，包含原文摘录、定位、笔记与旧资料备注。旧的资料备注仍显示在笔记面板，不自动改成新笔记。
- Word / 文本：TXT、MD 按文本阅读；DOCX 提取文字阅读，文字块编号不代表 Word 排版页码；旧 DOC 或未知编码请下载查看，仍可在侧栏写笔记。
- 文件版本：笔记绑定原文件 hash；文件变化后保留旧版本笔记，但不将旧高亮套到新文件上。删除资料时关联阅读记录和笔记也会移除，请按需提前导出。

过去问的对应答案可在「资料」页签中打开。募集要项核对窗口里的「阅读与笔记」会在新标签打开对应页，保留正在核对的内容。

### 阅读页 AI 问答

阅读页右侧切换「AI」，使用「AI 管理 → 功能分配 → 阅读与笔记问答」指定的连接与模型，可独立于工作区聊天选择。阅读会话按当前文件及 hash 单独保存；打开 AI 面板或选择原文不会发送推理请求，点击「发送」后才开始。API 模型需支持工具调用，密钥仅保留在本地服务进程中。

- 直接提问：会带上当前页的部分原文，助手可按需读页、搜索文字和查看本资料笔记；当前阅读对话不开放大学 / 研究室资料修改或其他文件读取。
- 选段提问：选择同一页的文字，点「问 AI」，原文先附到输入框，可以补充问题或移除附件后再发送。每次最多附 8,000 字，服务端会核对文件版本、页码和选段。
- 引用：回答中的 S 编号及来源卡片可点回原文。程序记录真实文件 hash、页码和原文；像素定位失败时仍可查看对应页，不编造高亮。原文匹配仅表示片段存在，理解与结论仍需结合文献核对。
- 存为笔记：点回答下的「存为笔记」，会带入笔记编辑器，保留来源摘录与定位；可修改后点「保存笔记」，不会自动覆盖已有草稿或结构化报考信息。
- 范围：目前为单份资料、分页文字问答；扫描件无文字时会明确说明，未接入图像问答、联网检索或多篇综合。PDF 文字解析沿用 300 页 / 200 万字限制；DOCX 页码是逻辑文字块，旧 DOC 请转换后使用。

会话中可停止回答、恢复历史和新建对话；模型配置修改后开始新对话。资料片段、提问与按需读取的本资料笔记会交给所选模型处理，是否联网取决于所用模型服务。

顶部「返回上一级」按页面层级返回，大学清单和修考之路返回申请总览，首页返回按钮不可用。桌面左侧可以快速打开申请总览、大学清单、已有大学和当前研究科 / 专攻；手机点击顶部菜单打开导航。右上角主题菜单可选浅色、深色或跟随系统，选择会在当前浏览器中保留。侧边栏和页脚的「本地工作区」可查看资料保存位置，并复制文件夹路径。

### 申请总览

打开网站根地址或旧入口 `/japan-grad` 也会自动进入申请总览；大学清单使用独立地址 `/japan-grad/universities`，从左侧菜单进入。

首页仅汇总已标记「想考」的研究室，没有目标时可直接选择研究室或新增大学。近期节点支持 7 / 30 / 90 天切换，显示未完成的日程及正在进行的时间段，已过日期不会冒充未来安排。考试日期沿用各专攻最新记录年份；常规时段等无法识别的日期不会自动推测。

待办可以按全部、今天截止、逾期筛选；勾选完成后与研究室材料清单同步，失败会保留原状态并提示。研究室进度展示所有老师的联络阶段汇总、材料百分比和下一个节点。待补信息按大学预算、专攻要求、研究室资料分组，共用的大学和专攻只显示一次；点击可直接编辑或进入对应资料页。首页材料进度只统计已建立的材料，不包含普通待办，未建清单不代表已完成。

- 大学：填写 QS 排名、榜单年份和国立 / 私立 / 公立 / 国公立类型。QS 为手动录入，可保存排名区间。
- 地区：先选「所在地域」，再选「都道府县」。地域分为北海道、东北、关东、中部、近畿、中国、四国、九州和冲绳，覆盖全部 47 个都道府县。都道府县可输入中文或日文搜索，切换地域后只显示对应选项。城市、校区和详细地址可继续填在「城市 / 详细所在地」；旧所在地文字保留，能识别的都道府县会自动预选。
- 总费用：国立、公立、国公立默认入学金 282,000 日元、年度学费 535,800 日元，可编辑或恢复默认；私立学费手动填写。房租 / 寮费和生活费按月填写，生活费不含房租。首年总费用 = 入学金 + 年度学费 + 12 ×（月租 + 月生活费）；两年只收一次入学金，其余费用乘以两年。所有项目可填零；未填写项目显示待补充，此时合计为已知费用小计。恢复默认学费保留房租、生活费和备注。额外支出可记在费用备注中。
- 寮 / 学生宿舍：选择待确认、可申请或不可申请，记录申请官网、资格、申请时间、入住年限等。可申请不代表已获入住资格；预算中的房租需按实际住宿方案填写。
- 校徽：在新增或编辑大学时上传 PNG、JPG、WebP 图片，最大 3 MB。可以预览、更换或移除，保存大学后生效；取消编辑保留原校徽。校徽同时展示在大学清单、详情和对比中。
- 大学清单：点击大学卡片即可进入详情；卡片上的对比勾选独立操作。
- 新增资料：点击「新增募集要项」「新增过去问」或老师论文库中的「新增论文」，在弹窗内拖拽一个文件到选择区，也可以点击选择区打开文件选择窗口。每次仅支持一个文件；选中后显示文件名与大小，可更换或移除。确认年份、标题后点击「保存到本地」，取消不会新增资料。支持 PDF、DOC、DOCX、MD、TXT，单个文件最多 50 MB。
- 研究室：进入专攻后新增研究室，记录研究方向、官网和特殊考试 / 出愿要求，再维护研究室内的老师。编辑老师可调整到同一专攻下其他研究室，论文、邮件跟随原老师保留。旧老师按原研究室名称归组，未填写名称时暂用「老师姓名研究室」。
- 修考之路：在此页面点击「新增研究室」，直接搜索或按大学筛选已整理的研究室，可一次勾选多个加入，也可全选当前结果。已加入的研究室会标记出来，避免重复；取消不会新增目标。在研究室点击「想考」也可加入。可搜索并勾选 2–6 个研究室横向比较，选择具体考试年份或各专攻最新记录。年度开销包含学费、房租和生活费，不含一次性入学金；首年总费用另列。考试与通用出愿信息参考所属专攻，研究室特殊要求独立展示。
- 考学经历：老师详情或研究室入口打开完整经历表，按未联系、首封、回复、预约面试、已面试、内诺、结果展示不同内容；可展开完整总表。论文和研究方向取自老师资料，要求参考研究室与专攻；首封和往来信件来自「邮件往来」。面试可保存准备、实际时间、问题与回答；内诺可关联来信原文、上传单个文件并标记签署状态；结束可记录结果与结果邮件。状态切换保留所有已保存内容，日期需要真实记录，不自动填当天。
- 邮件与历史：邮件保存时选择归属经历，预约面试之前自动更新首封 / 回复阶段；后续阶段由你确认。新建经历只填写名称，上一段归档且其邮件、内诺文件继续归属原经历。草稿需保存后才进入工作区；本次页面会话保留的未保存输入在浏览器刷新后会丢失。应用不代发邮件。已引用邮件被删除 / 移走时保留当时原文。
- 联络看板：修考之路按想考研究室内每位老师展示当前经历，拖动卡片或下拉改变阶段；实际邮件仍作为早期阶段依据。主要老师用于研究室摘要与导出。联动的时间线节点同步经历日期，个人节点可选择是否联动。
- 时间线与日程：按日本时间（JST）汇总出愿、考试、教授联络和待办的明确日期，可查看 3 / 6 / 12 个月甘特图、倒计时和时间重叠提示。同一专攻共享的同一场考试不会重复提示，同日安排需进一步确认时段与地点。常规月份或不明确日期不推测。支持导出当前范围 `.ics`，导入系统日历后可使用提前一天提醒，出愿窗口另有截止前一天提醒；工作台页面关闭后不提供独立的后台通知。
- 材料：研究室中独立管理研究计划书、推荐信、成绩单等申请材料，记录 0–100% 准备进度和备注。可选「智能导入」读取已核对的募集要项出愿材料，或「手动新增」；也可添加常用材料模板。
- 待办：与材料分开管理，每项新待办都要填写日期。智能导入会从已核对的募集要项中生成出愿开始、出愿截止、笔试、面试和放榜待办；不完整或不确定的日期不会被自动推测。待办同步到申请总览和时间线。
- 导出 Excel：点击按钮先打开选择窗口，可搜索、按大学筛选并勾选想考研究室，导出数量不限。已有对比勾选会带入窗口，否则不预选研究室。逐项选择费用、语言要求、考试科目 / 时间、地域、QS、联络或材料进度等属性，支持常用对比、费用预算、报考安排快捷选择及表格预览。大学与研究室名称固定保留，其余未选属性不写入文件。默认一张对比表，可按需另附考试明细、独立的材料明细与待办明细或导出说明；明细同样只保留所选属性，额外保留年份 / 批次或项目名称识别各行。考试统一按最新、指定或全部已记录年份导出。费用缺项时合计留空；同时勾选所需费用输入列时合计可重算，仅勾选合计时导出当前数值快照，不附带其他费用输入。
- 专攻：募集要项与过去问分为独立卡片清单。上传时选择年份，点击卡片进入阅读与笔记；卡片右上角可查看和编辑资料，原文件仍可下载。
- 出愿信息：在专攻详情的考试表格上方点击「编辑出愿信息」，填写出愿开始、截止时间段、所需材料和语言要求（日语 / 英语成绩、有效期、免除条件等）。研究室有独立语言要求时可在「编辑研究室」中填写，留空则参考所属专攻；语言要求可单独参与对比与 Excel 导出。可记录具体日期或每年的常规时段；材料一行一项，保存后展示为清单。这些通用要求独立展示，个别年份的特殊变化填在对应考试记录的备注中。
- 历年考试信息：以表格对比考试年份、考试科目、笔试时间、面试时间和结果发布时间，独立的「备注」列记录当年出愿日期、追加材料等特殊变更。点击「新增考试记录」可单条填写，也可编辑、删除；同一年可以分多个批次记录。仅考试年份必填，时间可记录日期、时段或「待公布」，未填写内容明确显示待填写。旧记录中的原考试时间保留，可在编辑时整理到新时间栏。
- 批量录入：点击「批量录入」，每行填写一个年份的考试信息，可「添加一行」或按起止年份「生成年份」，并可填写备注。也可展开「粘贴多行数据」，复制带表头的表格内容，备注列会自动识别；不带表头时，依次为年份、科目、笔试、面试、结果发布时间、批次、备注。点击「追加到表格」后检查保存。每批最多 50 行；空白行忽略，重复的年份 / 批次需处理后再保存。批量保存一次提交全部有效行，取消不会新增记录。手机上可以在表格内横向滑动查看其余列。
- 过去问：选择考试年份上传；点击某份过去问的「上传答案」，答案会关联试题和年份。
- 老师：点击老师卡片即可进入独立详情页；心仪、编辑按钮独立操作。切换「论文库」上传论文文件、保存作者、会议/期刊和阅读笔记；切换「邮件往来」复制粘贴收发邮件，记录日期和后续行动。支持刷新页面、通过地址直接打开老师详情，点击面包屑中的研究室名称返回老师清单。

募集要项支持本地原文读取、AI 提取与草稿核对。支持 PDF、DOC、DOCX、MD、TXT，均保存原文件；PDF 在工作台内阅读，文本按原文显示，DOCX 支持提取文字预览，旧 DOC 下载查看。

## 旧资料、备份与删除

首次打开空工作区时，如果同一浏览器地址下存在旧原型资料，会复制到本地数据库，并保留原浏览器数据与备份。不同端口属于不同浏览器地址；原型 `5666` 地址中的数据，需要先在开发服务相同地址完成迁移。

备份时先关闭服务，再复制整个 `JapanGradWorkspace` 文件夹。迁移到另一台电脑时，将该文件夹放到同样的位置再启动软件。不要在服务运行时单独复制 `workspace.db`。

桌面版从 0.1.1 起，可在「帮助 → 检查更新」检查新 Release，也可在同一菜单设置自动检查和更新通道。0.1.0 需要手动覆盖安装一次新版；以后按提示下载、确认安装。Windows 使用 MSI 向导，Mac 将 DMG 内的 JUAI 拖入应用程序替换。资料始终独立保留。

首次运行不同版本时，桌面版会在数据库迁移之前自动备份完整工作区到旁边的 `JapanGradWorkspace.backups` 文件夹。备份包括已保存的 SQLite WAL 数据和上传文件；备份失败会停止启动。恢复时退出所有使用该目录的 JUAI 服务，先保留当前目录副本，再将完整备份复制回原工作区。

移除文件时会移入 `.trash`；删除大学、研究科、专攻或老师会删除关联的数据库记录、文件索引和邮件，原始文件仍留在原目录。建议删除前先备份工作区。

可通过 `JAPANGRAD_WORKSPACE` 指定其他工作区，`JAPANGRAD_PORT` 修改端口。服务只监听本机 `127.0.0.1`。

如果已有服务占用端口，请先关闭旧启动窗口，然后重新启动。

## 手动编辑时间线与日程

进入「修考之路 → 时间线与日程」，点击「新增日程」，或研究室行中的「+ 添加」。默认节点为「首次联络、内诺、出愿、笔试、面试、放榜」，也可选择「自定义」填写自己的节点名称，默认节点名称同样可以修改。出愿支持开始 / 截止时间段，其他节点可单日或跨日，可填写具体起止时间（JST）与备注。未勾选完成表示计划中的安排，实际完成后可更新状态。

时间线仅显示简短节点名称；鼠标悬停或键盘聚焦时显示完整名称、具体日期 / 时间（JST）和备注。点击节点即可编辑。近期提醒、时间重叠说明与日程清单默认收起，按需展开后也可编辑。手动修改按研究室保存；来自专攻、教授或材料清单的日期可调整或隐藏，隐藏后可点击该研究室的「恢复来源日程」。修改会同步更新图表、倒计时、近期节点和 .ics 导出。列表包含显示月份之外的已记录日程，方便查找与移动日期。

Excel 导出可勾选「时间规划」中的首次联系、内诺、出愿、考试与结果，或使用「修考日程」快捷方案。

## 特殊入学项目

左侧「管理 → 特殊入学项目」（`/japan-grad/special-programs`）独立整理 SGU、英语授课、联合培养、双学位等项目。

- 新增项目后，整张卡片可点击进入详情；支持编辑、删除、关注，以及按名称 / 院校 / 语言搜索，按类型和申请状态筛选。
- 可关联已有大学、研究科与专攻，详情页可直接进入关联档案；学校尚未加入大学清单时，可先记录院校名称。删除项目只删除项目本身。
- 分别记录学位、授课语言、入学时间、项目官网、申请资格、语言要求、出愿材料、考核方式、费用、奖学金和备注。出愿时间支持开始 / 截止日期，另有考核及放榜日期。
- 状态包括了解中、准备申请、已申请、已录取、已结束。项目没有预设招生事实，具体要求和日期请按对应项目官网填写。
- 数据保存在工作区 `workspace.db` 的独立项目表中，包含在完整工作区文件夹备份内。仅导出大学清单 JSON 不包含该项目表。多页面修改有版本冲突保护；关联学校被删除后，项目原有院校名称仍保留，重新编辑时可取消或重新选择关联。

## 新增档案与网址解析

大学、研究科、专攻、研究室的「新增」入口统一先选择「手动新增」或「网址解析查询」。手动方式沿用原表单，编辑已有档案仍直接进入编辑表单。大学清单采用紧凑卡片，显示本地校徽、国公立 / 私立、QS 世界排名及日本排名；日本排名单独注明来源与年份，未查明不填。

网址解析统一填写五项：官网网址、入学年份、申请身份、备注、查询方式（本地 Agent / API）。查询方式选择实际的已启用连接，不会改变全局默认 AI。申请身份可写「修士・外国人留学生」等，备注可补充选拔类别或重点。年份和身份默认从「设置 → 个人信息」预填。

独立的「官网信息收集」菜单已移除。`/japan-grad/collection?job=任务ID` 保留为解析进度与结果页，也能切换查看历史任务。浏览器连接统一移到「设置 → 浏览器连接」。

网址解析结果页显示四阶段进度：「等待AI启动 → AI搜索中 → AI总结中 → 已完成」。阶段跟随读取、工具调用、总结输出和草稿校验状态更新；「已完成」表示 AI 草稿已生成，核对后才能正式建档。失败或停止时保留所在阶段及来源，重试继续更新。进度按阶段展示，不作为剩余时间或精确百分比估算。

1. 首次启用时默认复制已配置工作区助手的连接与模型，后续独立管理；也可在「AI 管理 → 功能分配」为「官网信息收集」另选支持工具调用的本机 Codex 或 API。
2. 从对应层级点击新增并选择网址解析。主链接对象按该入口设置，确认页仍可修正；来自已有大学 / 研究科 / 专攻的新增操作会带上对应上级作为辅助信息，最终核对所属关系后再生成。
3. 默认勾选「查找对应募集要项并总结申请信息」。系统先从实际出现的招生链接中优先读取相关入口；已下载要项可定位并读取关键页，再由 Agent 继续查找。重点总结申请资格、出愿时间、材料、语言要求、考核科目、考试与放榜、费用。大学任务查大学院通用招生信息，具体对象任务追查所属研究科 / 专攻的对应要项。公开网页直接读取，必要时使用已授权 Chrome；访问记录和已读页范围会显示在任务中。
4. PDF 按页 / 关键词阅读，扫描页在本机 OCR 可用时按需识别，原文件不变。字段附原文摘录、来源链接和页码；无法核对引用的字段留空，不影响其他有效结果。
5. 顶部「主链接对应」显示识别层级，可修正。大学链接只建立大学；研究科建立大学与研究科；专攻补齐大学 / 研究科 / 专攻；研究室再补研究室；老师再补老师。仅建立主对象和真实上级，按名称 / 官网匹配已有档案，不扩建无关下级。缺失的真实上级名称仍需补充。已有内容冲突的字段默认不选，替换需确认。募集要项摘要分项展示证据；具体时间需单独核对年度、研究科、专攻及选拔类别后才能采纳。未找到或范围不明确时显示醒目提示，基本信息仍可单独建档。
6. 点击「确认并生成档案」，一次保存所选层级及上级。主对象详情页显示所采纳的募集要项摘要、适用范围、引用与原件。含专攻的任务可将考试记录写入专攻、募集要项归档到专攻；含老师时可归档论文，含研究室时可加入想考清单。只建大学 / 研究科时，原件留在本任务来源并可从详情页打开，不为存文件强建专攻。缺失年份的附件需核对归档年份。完成后可直接进入主对象与各级档案。入库检查工作区修订、所属关系、字段范围及文件 hash。

### 连接用户 Chrome

进入「设置 → 浏览器连接」，在 Chrome 打开 `chrome://inspect/#remote-debugging`，启用“Allow remote debugging for this browser instance”，允许本机连接，再点击「检查并连接浏览器」。也可指定调试端口。网址查询默认公开网页优先，必要时使用已授权 Chrome。

收集器只创建并关闭自己的标签页，读取正文与链接，不改动已有标签页，不提交表单、不发送邮件；登录与验证码由用户处理。未连接浏览器时，公开网页仍可读取。软件包包含连接组件，不下载独立浏览器。

第一版每任务最多 12 个来源，其中最多 3 份 PDF；PDF 单个 40 MB、资料合计 100 MB，解析沿用 300 页 / 200 万字上限。Agent 有调用次数和运行时长边界，未读页面不声称已读。失败或停止后来源保留；重试复用缓存并重新调用模型，要读取官网新变化可新建任务。当前实现受限网页读取与相关链接导航，没有任意脚本、账号操作或全站爬取。自动下载仅支持公开 PDF；需登录的 PDF 或其他格式可由用户下载后上传现有资料库，不会转发浏览器 Cookie 给模型。

每次探索最多 20 次工具调用，接近上限时提示 Agent 收尾；达到次数、上下文或整理轮次边界时，自动进入无工具的最终整理阶段，根据已读来源生成待核对草稿。不会因读取次数用完而丢弃已有资料。失败后可选「继续收集」或「用已读资料生成草稿」；后者不再抓网页或读取新页面，仍会调用当前配置的 AI，未读取内容保持为空。来源片段过长时会截断并标记，原始来源快照和 PDF 保留。

AI 原始结果在核对前保存在本机。格式不完整、字段重复冲突或引用不匹配时，单项留空并提示，其他有效字段继续保留。若已有原始结果，「用已读资料生成草稿」会先重新核对该结果，不重复调用模型；完全没有有效字段时仍会明确报错，不生成空档案。

### 校徽与排名

解析时会从官网真实图片候选中查找大学校徽，确认页可预览、勾选，并保存成不超过 512 像素的本地 PNG；已有校徽默认不替换，替换需确认。支持公开 PNG / JPG / WebP，以及无外部依赖的安全 SVG 转换。无法取得或无法确认时，可取消候选并用大学编辑页手动上传。排名只引用实际读到的资料，日本位次必须注明榜单口径，不能根据收藏清单计算全日本排名。

## 设置

左侧「管理 → 设置」包括个人信息和浏览器连接。个人信息可填写称呼、邮箱、院校、专业、学历、语言成绩、研究兴趣、备注，以及默认入学年份与申请身份。数据仅存本地 `workspace.db`，网址查询只自动预填年份和身份，其余内容由用户自行加入查询备注。多页面保存有版本保护。

连接浏览器时，在 Chrome 打开 `chrome://inspect/#remote-debugging`（Edge 为 `edge://inspect/#remote-debugging`），开启远程调试后，返回 JUAI 点击「检查并连接浏览器」，再到浏览器的授权提示中选择允许。JUAI 会读取浏览器提供的 WebSocket 地址，兼容不提供 `/json/version` 的新版 Chrome。只有真实授权连接成功后才显示「已连接」；浏览器重启后需要重新连接。

特殊入学项目的新增也提供手动 / 网址两种方式。网址查询使用同样的五项表单，结果核对后只生成特殊项目档案，保留院校名称、申请要求及募集要项摘要，不自动扩建大学层级。原件可从项目详情页的募集要项区域打开。

## AI 管理

左侧导航「AI 管理」（`/japan-grad/ai`）默认只提供两种接入方式，聊天侧栏及募集要项里的配置链接也会进入这里。

1. **连接本地 Agent**：当前支持本机 Codex，点击即检测程序、已有登录和可用模型。已登录时自动连接；未登录会打开登录入口，完成后点「我已登录，继续连接」。无需填写 API Key。模型和程序路径可在卡片内的可选项中调整。
2. **使用自己的 API**：选择 DeepSeek、OpenAI 或其他兼容 API，填写地址与 API Key，点击「保存并使用 API」。常用服务地址已预填；留空模型时自动读取服务商目录并选择聊天模型，目录不可用时展开「模型与接口选项」手动填模型 ID。读取目录不会启动推理，不代表实际推理已经验证。

成功保存任一种方式后，官网信息收集、工作区助手、阅读与笔记问答、募集要项提取统一启用并使用该连接，不需要逐项分配。旧对话保留原来的模型，新配置从新对话 / 新任务生效。已有权限范围保持原设置，不因快速连接自动扩大。原有连接和历史记录会保留；在点击保存前不会改动原有功能分配。

### 高级设置（可选）

页面底部展开「高级设置」，可继续管理多个连接、按功能分别选模型及管理外部 MCP 授权。平时无需逐项配置。

1. **模型连接**：新增 DeepSeek、OpenAI、OpenAI 兼容 API 或本机 Codex。可给连接命名、填写地址 / 密钥 / 默认模型、设置流式输出、工具 / 图像能力、JSON 格式和输出上限，编辑、停用或删除连接。同一服务可保存多个账户，密钥按连接隔离。
2. **读取模型目录**：API 连接点击「读取模型列表」；Codex 点击「连接 / 检测」。这一步不发送文档与聊天，也不启动推理；模型目录不可用时仍可手动填写 ID。Codex 沿用本机账户，未登录时到「Agent 与权限」完成登录后再次检测，Luna 仅在账户目录可用时出现。
3. **功能分配**：官网信息收集、工作区助手、阅读与笔记问答、募集要项提取分别选择连接和模型。模型留空沿用连接默认值；例如阅读用本机模型，募集要项用另一个 API。同一 DeepSeek 连接也可按功能分别开关思考。保存后新对话 / 新提取任务生效；历史对话保留原连接。关闭功能或停用 / 清除连接，会停止对应运行请求。
4. **Agent 与权限**：管理本机 Codex 登录、工作区助手可读取的专攻和可提出修改的类型；全部取消修改类型即只读。权限收紧后旧工作区会话需新建，防止继续使用旧授权上下文。阅读问答只读当前资料。外部 Agent 授权可创建 / 下载 MCP 配置、查看范围及最近使用时间、撤销授权。

DeepSeek 预设使用官方 `https://api.deepseek.com` 的 Chat Completions，提供 `deepseek-flash` / `deepseek-v4-pro` 预设并支持读取账户实际目录。支持思考开关 / 强度、流式与非流式、工具调用上下文回传，以及 JSON Object 提取后服务端校验。图片能力按具体模型目录判断；不把所有 DeepSeek 模型都视为支持图片。旧 `deepseek-chat` 等模型名不自动替换，需按服务商实际可用 ID 更新。参考 [DeepSeek 官方调用文档](https://api-docs.deepseek.com/)、[思考与工具调用](https://api-docs.deepseek.com/guides/thinking_mode/)、[模型目录](https://api-docs.deepseek.com/api/list-models/)。

API 密钥不写入 SQLite、浏览器持久存储或导出配置，服务重启后需重新填写。更换连接地址 / 协议会清除该连接密钥；删除连接前需先解除功能分配。读取目录成功只验证了目录访问，不等于模型推理已验证。

## 募集要项分析与 Agent 接入

1. 从专攻详情的「募集要项分析」或募集要项文件详情进入分析页面，直接选择该专攻的资料、资料年度、学位和选拔类别。每任务 1–10 份文件，总计 100 MB，单文件 50 MB，PDF 最多 300 页。
2. 点击「读取资料，准备分析」。页面显示「AI 管理 → 功能分配 → 募集要项提取」所选的连接与模型；点击「前往 AI 管理」可更换本机 Codex / Luna 或自己的 API，不影响另外两项功能。
3. 点击「AI 提取为草稿」。可展开「分析范围与扫描件处理」按文件填写页码，如 `1-5,8,12-14`，留空为全文。自动模式优先读取文字，文字较少的 PDF 页在本机 OCR 后交给 AI；没有本机 OCR 时需要支持图片的模型。Apple Silicon 软件包内置 macOS Vision 日语 / 英语 OCR，其他环境可使用带 jpn 语言包的 Tesseract。表格错列或文字乱码时可手动选择所有所选页 OCR / 图片分析。每次最多 120 页文字 / 24 页 OCR / 18 页图片、24 万字和 12 批模型请求；超限请缩小范围。
4. 点击「核对 AI 草稿并填表」，选择字段、修改内容并确认出处。文字引用会检查原文匹配，OCR / 图片引用标记为「需看图核对」。名称不一致只提醒，继续提取通用要求；时间属于具体研究科、专攻或选拔类别而对应关系不明确时，会保留明确日期、显示适用对象与「查看时间所在原文」，单独勾选确认后才能采纳。无法确定年份或多个候选时间仍留空提示。出愿与语言要求更新到专攻资料；采纳考试科目 / 日期时明确选择已有考试记录或填写考试年份 / 批次新增；材料可选择研究室生成清单。其他要求与确认记录保存在分析页。旧草稿不自动重写，可重新提取应用新策略。
5. 提取进度、停止和最近结果保留在页面。中途失败时可核对已完成批次的部分草稿，但未处理页不能视为没有要求；服务重启不会自动重试。模型调用沿用本机账户额度或 API 服务商计费，只有点击开始后才提交所选原文 / 图片。
6. 仍可使用「其他方式：外部 Agent / 导入分析结果」：下载 ZIP 任务包，生成 result.json 后拖拽 / 选择单个 JSON 文件导入；或通过「Agent 工作区接入」配置 MCP 回传。令牌仅创建时显示，可撤销。

采纳时检查来源 hash、专攻归属和工作区修订；替换已有内容需确认。AI 生成草稿后不会直接覆盖信息表。阅读页的普通问答仍按文字层读取；本节 OCR / 图片识别用于专攻募集要项提取，不自动改变原文件或阅读器文字层。

## 本地 Agent 信息文件接入

在「修考之路 → Agent 工作区接入」选择授权专攻与信息文件权限。可以选择只读、读取并编辑，或保留原来的仅募集要项分析权限。编辑时逐项授权专攻、研究室、老师基本资料、大学和研究科；大学 / 研究科为共享资料，默认不授权编辑。

创建后可复制 / 下载通用 MCP JSON 或 Codex TOML，也可下载完整配置 ZIP，包含两种配置、AGENTS.md、使用说明、授权范围和忽略令牌配置的 .gitignore。在独立文件夹中打开本地 Agent，将所需配置合并到客户端 MCP 设置后重新加载；保持 JUAI 服务运行。无需把源码目录交给 Agent。此轮不自动修改用户的客户端全局配置。令牌只在创建窗口返回，服务端只保存 hash；遗失时撤销并重新创建。旧连接不会自动获得信息文件权限。

建议对 Agent 说：“先查看 JUAI 连接状态和授权范围，列出可编辑的信息文件，再按我的要求更新资料。保存前说明字段变化，缺失信息不要猜测。”

| MCP 工具 | 用途 |
| --- | --- |
| get_connection_status | 确认服务连接与权限，不返回令牌 |
| get_information_workspace | 读取授权、字段 JSON Schema、地域选项和操作规则 |
| list_information_files | 搜索 / 分页列出逻辑 JSON 文件与可写状态 |
| read_information_file | 读取开放字段、父级路径及当前 SHA256 |
| write_information_file | 按原 hash 保存信息并同步工作区；提供唯一 requestKey 和摘要 |
| list_information_changes | 读取本连接最近 50 项修改摘要 |

信息文件路径如 `majors/<id>.json`、`labs/<id>.json`，由服务映射到 SQLite 中的现有记录，不是磁盘文件路径。内容使用 `{schemaVersion:1, kind, id, data:{...}}`，ID 和所属关系不可变；`data` 中未提供的字段保留，字符串可用空字符串清空。费用按整数日元字符串记录，材料和考试数组按工具返回的 Schema 填写。新建 / 删除实体、关系调整、邮件与考学经历、上传原文件、代码及数据库不通过这些信息工具开放。工具授权只限制 JUAI MCP 能力，不限制 Agent 客户端自身已有的 Shell / 系统文件权限。

写入重新检查令牌、专攻范围和资料类型；路径仅接受预定义逻辑路径，不访问任意磁盘路径。全工作区校验、资料变更与历史写入在本机服务事务中完成；hash 冲突要求重读合并，同一个 requestKey 重试不会再次应用。升级新增数据库 migration 6，保存 Agent 信息修改历史。

在接入窗口底部查看修改前后对照、刷新连接最近使用时间，或撤销单项修改。撤销仅恢复该项改变的字段，保留其他资料；字段之后有新变化时拒绝撤销，原记录仍可查看。普通页面约每 15 秒及重新聚焦时检查新修订；打开编辑弹窗时暂停自动更新，保存冲突不会静默覆盖 Agent 改动。

募集要项分析仍使用原有提取、证据与待核对草稿流程。信息编辑用于用户明确要求的资料维护，不替代来源核对。

## 网页 AI 资料助手（自带 API）

右上角「AI 助手」打开网页对话框。首次到「AI 管理」添加连接，并给工作区助手分配模型、授权专攻；返回侧栏点击「新对话」即可使用。每个对话固定自己的模型地址与资料范围，改配置后新建对话。可以恢复历史、停止回答、删除对话，或打开「修改记录」对照与撤销已保存的资料。

支持 OpenAI Responses 与 OpenAI 兼容 Chat Completions；本机模型服务可使用 localhost / 127.0.0.1 HTTP，远程 API 使用 HTTPS。模型必须支持函数工具调用，兼容性取决于服务商与模型；较新的 OpenAI 模型使用 Responses。默认流式显示，可在设置关闭流式以适配其他服务。Base URL 自动补充对应接口路径，不接受 URL 中的密钥参数。

助手可以搜索 / 读取授权专攻及所属大学、研究室、老师基本资料，查看已核对的补充报考要求，并提出资料修改建议。所有写入先显示修改前与建议值；点击「确认修改」后才保存。确认前再次校验 hash 和范围，复用信息文件服务的字段校验、幂等保存与撤销历史。只读模式不提供修改建议工具。工作区对话不直接读取原始 PDF / Word、邮件、考学经历或系统文件；阅读页另设仅当前文档的只读问答，募集要项正式字段采纳继续使用专攻分析页面。

API 密钥只放在本地服务进程内存，不写入 SQLite、浏览器持久存储、对话日志或配置包；重启服务后重新填写。模型地址和非敏感设置、对话与建议保存在本机 SQLite。用户点发送后，对话及本轮工具读取的授权信息会发送到其配置的模型服务；没有内置平台模型密钥。

使用本地 Node.js 编排工具调用，共用已有资料权限层，无 LangChain 依赖。本机 Codex 已通过 App Server 接入，外部 Agent MCP 继续可用。DeepSeek 的思考上下文仅在服务端用于维持工具对话，不作为可见回答或密钥配置返回。

技术边界：数据库追加 migration 7（设置、对话、建议表）；最近 16 条对话进入模型上下文，旧对话仍保留在本机。每轮最多 8 次模型请求、20 次工具调用、5 项修改建议，每个模型请求最多输出 4096 token，总处理时间 3 分钟，同时最多 2 轮运行。工具结果限制大小；请求取消、中断、服务重启或 hash 冲突均有明确状态。没有通用 Shell、任意文件读写、自动发送邮件或模型直接保存资料的工具。

接口依据：[OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling)。本机 Codex 另一条路线依据：[Codex App Server](https://developers.openai.com/codex/app-server)。

## 本机 Codex 与并排助手侧栏（2026-10-15）

右上角「AI 助手」现在展开固定在右侧的工作面板，主页面同时缩窄并重新排版。拖动两栏分隔线调整宽度，双击恢复默认；键盘左右键也可调整，宽度记在本机浏览器。收起后主页面恢复；较窄窗口使用全宽助手视图。资料与对话可以并排查看。

点击「连接本机 Codex」，自动检测 Codex CLI、沿用已有登录 / 模型配置，并创建 JUAI 专用网页会话。无需填写 API 密钥或手动安装 MCP 配置。模型列表由本机 Codex 返回，不硬编码；在设置中可选择模型、专攻和资料范围，自动检测失败时可填写程序绝对路径。未登录时提供官方登录入口。

也可点击「复制指令给本机 Agent」，让本机 Agent 只调用 JUAI 的连接接口完成这项连接。网页检测到新会话后载入。此指令帮助连接 Codex，不会让任意外部 Agent 自动变成网页聊天引擎，也不导入 IDE 现有聊天记录。其他 Agent 要直接在网页回复仍需实现其对话适配器。

实现使用 Codex App Server 的 JSONL / STDIO、初始化、账户状态、模型列表、临时线程、流式消息和动态资料工具。每轮创建独立临时线程，JUAI 自己保存聊天历史并提供最近上下文。程序在独立临时目录运行，采用随机名称的只读文件权限配置，命令、代码执行、外部应用、hooks、其他 MCP 与插件在该接入会话中关闭；权限未正确采用时拒绝启动推理。不修改用户的 Codex 全局配置，不读取或复制账户令牌。登录、模型服务与额度由本机 Codex 的配置负责。

本机 Codex 复用网页助手的资料范围、读取后才能提议、字段校验、人工确认、冲突保护和撤销记录。取消或退出会中断 Codex turn；停止本地服务同时关闭它所启动的 Codex 子进程。用户自己的 API 模式继续可选。

无需新增数据库迁移，模型来源保存在原设置 / 会话 JSON 扩展字段中。接入依赖 Codex 的实验性动态工具与权限接口，旧版本或管理策略不兼容时会显示错误并停止，不放宽权限。

依据：[Codex App Server](https://developers.openai.com/codex/app-server)、[Codex Permissions](https://learn.chatgpt.com/docs/permissions)。本机实际连接初始化已读取到已有登录与可用模型，并核对选中的只读权限；未启动模型推理。代码检查包括 Vue 类型、Vite 构建、Node 语法及 diff；未运行自动化测试。
