# JapanGrad 本地工作台

适用于 Apple Silicon Mac。软件包内含运行时，不需要安装 Node.js、Java、数据库或开发依赖。

## 启动

解压软件包，双击「启动 JapanGrad.command」。保留启动窗口，浏览器会自动打开 `http://127.0.0.1:5667/japan-grad`。关闭启动窗口或按 Ctrl+C 停止服务。

系统默认浏览器即可使用。首次打开未签名的软件时，macOS 可能要求在系统设置「隐私与安全性」中允许打开；当前包是本地开发试用包，尚未签名、公证。

## 资料存在哪里

默认工作区为 `~/Documents/JapanGradWorkspace`（用户文稿文件夹）。软件目录与资料目录独立：移动或删除软件不会删除资料。

```text
JapanGradWorkspace/
├── workspace.db                    # 大学、专攻、考试记录、老师、资料索引和邮件
├── workspace.json                  # 工作区版本信息
├── university-logos/                # 上传的校徽原图片
├── majors/<专攻 ID>/
│   ├── guidelines/<招生年度>/       # 募集要项原文件
│   ├── question/<考试年份>/         # 过去问原文件
│   └── answer/<考试年份>/           # 关联答案原文件
├── professors/<老师 ID>/paper/<发表年份>/
└── .trash/                         # 在界面移除的 PDF，可恢复原文件
```

上传会复制原文件。所有文件保存在本地，不上传云端，可从工作台用浏览器自带 PDF 阅读器打开、下载，也可直接从文件夹查看。邮件正文保存在 SQLite 中。

## 使用

顶部「返回上一级」按页面层级返回，修考之路返回大学清单；大学清单已是根页面，返回按钮不可用。桌面左侧可以快速打开大学清单、已有大学和当前研究科 / 专攻；手机点击顶部菜单打开导航。右上角主题菜单可选浅色、深色或跟随系统，选择会在当前浏览器中保留。侧边栏和页脚的「本地工作区」可查看资料保存位置，并复制文件夹路径。

- 大学：填写 QS 排名、榜单年份和国立 / 私立 / 公立 / 国公立类型。QS 为手动录入，可保存排名区间。
- 地区：先选「所在地域」，再选「都道府县」。地域分为北海道、东北、关东、中部、近畿、中国、四国、九州和冲绳，覆盖全部 47 个都道府县。都道府县可输入中文或日文搜索，切换地域后只显示对应选项。城市、校区和详细地址可继续填在「城市 / 详细所在地」；旧所在地文字保留，能识别的都道府县会自动预选。
- 总费用：国立、公立、国公立默认入学金 282,000 日元、年度学费 535,800 日元，可编辑或恢复默认；私立学费手动填写。房租 / 寮费和生活费按月填写，生活费不含房租。首年总费用 = 入学金 + 年度学费 + 12 ×（月租 + 月生活费）；两年只收一次入学金，其余费用乘以两年。所有项目可填零；未填写项目显示待补充，此时合计为已知费用小计。恢复默认学费保留房租、生活费和备注。额外支出可记在费用备注中。
- 寮 / 学生宿舍：选择待确认、可申请或不可申请，记录申请官网、资格、申请时间、入住年限等。可申请不代表已获入住资格；预算中的房租需按实际住宿方案填写。
- 校徽：在新增或编辑大学时上传 PNG、JPG、WebP 图片，最大 3 MB。可以预览、更换或移除，保存大学后生效；取消编辑保留原校徽。校徽同时展示在大学清单、详情和对比中。
- 大学清单：点击大学卡片即可进入详情；卡片上的对比勾选独立操作。
- 新增资料：点击「新增募集要项」「新增过去问」或老师论文库中的「新增论文」，在弹窗内拖拽一个文件到选择区，也可以点击选择区打开文件选择窗口。每次仅支持一个文件；选中后显示文件名与大小，可更换或移除。确认年份、标题后点击「保存到本地」，取消不会新增资料。支持 PDF、DOC、DOCX、MD、TXT，单个文件最多 50 MB。
- 研究室：进入专攻后新增研究室，记录研究方向、官网和特殊考试 / 出愿要求，再维护研究室内的老师。编辑老师可调整到同一专攻下其他研究室，论文、邮件跟随原老师保留。旧老师按原研究室名称归组，未填写名称时暂用「老师姓名研究室」。
- 修考之路：在此页面点击「新增研究室」，直接搜索或按大学筛选已整理的研究室，可一次勾选多个加入，也可全选当前结果。已加入的研究室会标记出来，避免重复；取消不会新增目标。在研究室点击「想考」也可加入。可搜索并勾选 2–6 个研究室横向比较，选择具体考试年份或各专攻最新记录。年度开销包含学费、房租和生活费，不含一次性入学金；首年总费用另列。考试与通用出愿信息参考所属专攻，研究室特殊要求独立展示。
- 考学经历：老师详情或研究室入口打开完整经历表，按未联系、首封、回复、预约面试、已面试、内诺、结果展示不同内容；可展开完整总表。论文和研究方向取自老师资料，要求参考研究室与专攻；首封和往来信件来自「邮件往来」。面试可保存准备、实际时间、问题与回答；内诺可关联来信原文、上传单个文件并标记签署状态；结束可记录结果与结果邮件。状态切换保留所有已保存内容，日期需要真实记录，不自动填当天。
- 邮件与历史：邮件保存时选择归属经历，预约面试之前自动更新首封 / 回复阶段；后续阶段由你确认。新建经历只填写名称，上一段归档且其邮件、内诺文件继续归属原经历。草稿需保存后才进入工作区；本次页面会话保留的未保存输入在浏览器刷新后会丢失。应用不代发邮件。已引用邮件被删除 / 移走时保留当时原文。
- 联络看板：修考之路按想考研究室内每位老师展示当前经历，拖动卡片或下拉改变阶段；实际邮件仍作为早期阶段依据。主要老师用于研究室摘要与导出。联动的时间线节点同步经历日期，个人节点可选择是否联动。
- 时间线与日程：按日本时间（JST）汇总出愿、考试、教授联络和待办的明确日期，可查看 3 / 6 / 12 个月甘特图、倒计时和时间重叠提示。同一专攻共享的同一场考试不会重复提示，同日安排需进一步确认时段与地点。常规月份或不明确日期不推测。支持导出当前范围 `.ics`，导入系统日历后可使用提前一天提醒，出愿窗口另有截止前一天提醒；工作台页面关闭后不提供独立的后台通知。
- 材料与待办：进入研究室的同名栏目，添加研究计划书、推荐信、志望理由书、语言成绩等，并记录 0–100% 进度、截止日期和备注，也可导入常用清单或专攻要求。修考之路右侧显示全部目标的材料进度、待办及近期节点。材料清单与其他待办分开统计，未建清单的目标不会当作已完成。
- 导出 Excel：点击按钮先打开选择窗口，可搜索、按大学筛选并勾选想考研究室，导出数量不限。已有对比勾选会带入窗口，否则不预选研究室。逐项选择费用、语言要求、考试科目 / 时间、地域、QS、联络或材料进度等属性，支持常用对比、费用预算、报考安排快捷选择及表格预览。大学与研究室名称固定保留，其余未选属性不写入文件。默认一张对比表，可按需另附考试明细、材料与待办明细或导出说明；明细同样只保留所选属性，额外保留年份 / 批次或项目名称识别各行。考试统一按最新、指定或全部已记录年份导出。费用缺项时合计留空；同时勾选所需费用输入列时合计可重算，仅勾选合计时导出当前数值快照，不附带其他费用输入。
- 专攻：募集要项与过去问分为独立卡片清单。上传时选择年份，点击卡片查看资料详情和个人备注，PDF 点击「用浏览器打开 PDF」阅读，MD/TXT 可在浏览器看原始文本，DOC/DOCX 下载后用本机 Word / WPS 打开。
- 出愿信息：在专攻详情的考试表格上方点击「编辑出愿信息」，填写出愿开始、截止时间段、所需材料和语言要求（日语 / 英语成绩、有效期、免除条件等）。研究室有独立语言要求时可在「编辑研究室」中填写，留空则参考所属专攻；语言要求可单独参与对比与 Excel 导出。可记录具体日期或每年的常规时段；材料一行一项，保存后展示为清单。这些通用要求独立展示，个别年份的特殊变化填在对应考试记录的备注中。
- 历年考试信息：以表格对比考试年份、考试科目、笔试时间、面试时间和结果发布时间，独立的「备注」列记录当年出愿日期、追加材料等特殊变更。点击「新增考试记录」可单条填写，也可编辑、删除；同一年可以分多个批次记录。仅考试年份必填，时间可记录日期、时段或「待公布」，未填写内容明确显示待填写。旧记录中的原考试时间保留，可在编辑时整理到新时间栏。
- 批量录入：点击「批量录入」，每行填写一个年份的考试信息，可「添加一行」或按起止年份「生成年份」，并可填写备注。也可展开「粘贴多行数据」，复制带表头的表格内容，备注列会自动识别；不带表头时，依次为年份、科目、笔试、面试、结果发布时间、批次、备注。点击「追加到表格」后检查保存。每批最多 50 行；空白行忽略，重复的年份 / 批次需处理后再保存。批量保存一次提交全部有效行，取消不会新增记录。手机上可以在表格内横向滑动查看其余列。
- 过去问：选择考试年份上传；点击某份过去问的「上传答案」，答案会关联试题和年份。
- 老师：点击老师卡片即可进入独立详情页；心仪、编辑按钮独立操作。切换「论文库」上传论文文件、保存作者、会议/期刊和阅读笔记；切换「邮件往来」复制粘贴收发邮件，记录日期和后续行动。支持刷新页面、通过地址直接打开老师详情，点击面包屑中的研究室名称返回老师清单。

募集要项已支持本地原文读取、初步字段定位与外部 Agent 草稿核对。支持 PDF、DOC、DOCX、MD、TXT，均保存原文件；PDF 阅读交由浏览器自带阅读器处理，文本按原文显示，Word 文件暂不提供网页排版预览。

## 旧资料、备份与删除

首次打开空工作区时，如果同一浏览器地址下存在旧原型资料，会复制到本地数据库，并保留原浏览器数据与备份。不同端口属于不同浏览器地址；原型 `5666` 地址中的数据，需要先在开发服务相同地址完成迁移。

备份时先关闭服务，再复制整个 `JapanGradWorkspace` 文件夹。迁移到另一台电脑时，将该文件夹放到同样的位置再启动软件。不要在服务运行时单独复制 `workspace.db`。

移除文件时会移入 `.trash`；删除大学、研究科、专攻或老师会删除关联的数据库记录、文件索引和邮件，原始文件仍留在原目录。建议删除前先备份工作区。

可通过 `JAPANGRAD_WORKSPACE` 指定其他工作区，`JAPANGRAD_PORT` 修改端口。服务只监听本机 `127.0.0.1`。

如果已有服务占用端口，请先关闭旧启动窗口，然后重新启动。

## 手动编辑时间线与日程

进入「修考之路 → 时间线与日程」，点击「新增日程」，或研究室行中的「+ 添加」。默认节点为「首次联络、内诺、出愿、笔试、面试、放榜」，也可选择「自定义」填写自己的节点名称，默认节点名称同样可以修改。出愿支持开始 / 截止时间段，其他节点可单日或跨日，可填写具体起止时间（JST）与备注。未勾选完成表示计划中的安排，实际完成后可更新状态。

时间线仅显示简短节点名称；鼠标悬停或键盘聚焦时显示完整名称、具体日期 / 时间（JST）和备注。点击节点即可编辑。近期提醒、时间重叠说明与日程清单默认收起，按需展开后也可编辑。手动修改按研究室保存；来自专攻、教授或材料清单的日期可调整或隐藏，隐藏后可点击该研究室的「恢复来源日程」。修改会同步更新图表、倒计时、近期节点和 .ics 导出。列表包含显示月份之外的已记录日程，方便查找与移动日期。

Excel 导出可勾选「时间规划」中的首次联系、内诺、出愿、考试与结果，或使用「修考日程」快捷方案。

## 募集要项分析与 Agent 接入

1. 从专攻详情的「募集要项分析」或募集要项文件详情进入分析页面，直接选择该专攻的资料、资料年度、学位和选拔类别。每任务 1–10 份文件，总计 100 MB，单文件 50 MB，PDF 最多 300 页。
2. 读取 PDF / DOCX / MD / TXT，生成标题和明确日期定位的初步草稿。扫描页可交给支持图片理解的 Agent，旧 DOC 需转换后分析。
3. 点击「对照原文核对」，选择字段、修改内容并确认出处。出愿与语言要求更新到专攻资料；采纳考试科目 / 日期时明确选择已有考试记录或填写考试年份 / 批次新增；材料可选择研究室生成清单。其他报考要求和证据保存在分析页。
4. Agent 可以接收下载的 ZIP 任务包，生成 result.json 后拖拽 / 选择单个 JSON 文件导入；或通过「Agent 工作区接入」选择授权专攻并复制通用 MCP JSON / Codex TOML 配置。令牌仅创建时显示，可撤销。升级后请按客户端要求重新连接 MCP，以加载更新后的工具。

采纳时检查来源 hash、专攻归属和工作区修订；替换已有内容需确认。模型是否联网取决于自己的 Agent 配置，当前未内置独立 OCR 或模型 API。

## 本地 Agent 信息文件接入

在「修考之路 → Agent 工作区接入」选择授权专攻与信息文件权限。可以选择只读、读取并编辑，或保留原来的仅募集要项分析权限。编辑时逐项授权专攻、研究室、老师基本资料、大学和研究科；大学 / 研究科为共享资料，默认不授权编辑。

创建后可复制 / 下载通用 MCP JSON 或 Codex TOML，也可下载完整配置 ZIP，包含两种配置、AGENTS.md、使用说明、授权范围和忽略令牌配置的 .gitignore。在独立文件夹中打开本地 Agent，将所需配置合并到客户端 MCP 设置后重新加载；保持 JUAI 服务运行。无需把源码目录交给 Agent。此轮不自动修改用户的客户端全局配置。令牌只在创建窗口返回，服务端只保存 hash；遗失时撤销并重新创建。旧连接不会自动获得信息文件权限。

建议对 Agent 说：“先查看 JUAI 连接状态和授权范围，列出可编辑的信息文件，再按我的要求更新资料。保存前说明字段变化，缺失信息不要猜测。”

| MCP 工具 | 用途 |
| --- | --- |
| get_connection_status | 确认服务连接与权限，不返回令牌 |
| get_information_workspace | 读取授权、字段 JSON Schema、地域选项和操作规则 |
| list_information_files | 搜索 / 分页列出逻辑 JSON 文件与可写状态 |
| read_information_file | 读取开放字段、父级路径及当前 SHA256 |
| write_information_file | 按原 hash 保存信息并同步工作区；提供唯一 requestKey 和摘要 |
| list_information_changes | 读取本连接最近 50 项修改摘要 |

信息文件路径如 `majors/<id>.json`、`labs/<id>.json`，由服务映射到 SQLite 中的现有记录，不是磁盘文件路径。内容使用 `{schemaVersion:1, kind, id, data:{...}}`，ID 和所属关系不可变；`data` 中未提供的字段保留，字符串可用空字符串清空。费用按整数日元字符串记录，材料和考试数组按工具返回的 Schema 填写。新建 / 删除实体、关系调整、邮件与考学经历、上传原文件、代码及数据库不通过这些信息工具开放。工具授权只限制 JUAI MCP 能力，不限制 Agent 客户端自身已有的 Shell / 系统文件权限。

写入重新检查令牌、专攻范围和资料类型；路径仅接受预定义逻辑路径，不访问任意磁盘路径。全工作区校验、资料变更与历史写入在本机服务事务中完成；hash 冲突要求重读合并，同一个 requestKey 重试不会再次应用。升级新增数据库 migration 6，保存 Agent 信息修改历史。

在接入窗口底部查看修改前后对照、刷新连接最近使用时间，或撤销单项修改。撤销仅恢复该项改变的字段，保留其他资料；字段之后有新变化时拒绝撤销，原记录仍可查看。普通页面约每 15 秒及重新聚焦时检查新修订；打开编辑弹窗时暂停自动更新，保存冲突不会静默覆盖 Agent 改动。

募集要项分析仍使用原有提取、证据与待核对草稿流程。信息编辑用于用户明确要求的资料维护，不替代来源核对。

## 网页 AI 资料助手（自带 API）

右上角「AI 助手」直接打开网页对话框。首次点击「模型与权限」，填写自己的 API Base URL、模型 ID、密钥，选择接口与授权专攻；保存后即可对话。每个对话固定自己的模型地址与资料范围，改设置会开始新对话。可以恢复历史对话、停止当前回答、删除对话，或打开「修改记录」对照与撤销已经保存的资料。

支持 OpenAI Responses 与 OpenAI 兼容 Chat Completions；本机模型服务可使用 localhost / 127.0.0.1 HTTP，远程 API 使用 HTTPS。模型必须支持函数工具调用，兼容性取决于服务商与模型；较新的 OpenAI 模型使用 Responses。默认流式显示，可在设置关闭流式以适配其他服务。Base URL 自动补充对应接口路径，不接受 URL 中的密钥参数。

助手可以搜索 / 读取授权专攻及所属大学、研究室、老师基本资料，查看已核对的补充报考要求，并提出资料修改建议。所有写入先显示修改前与建议值；点击「确认修改」后才保存。确认前再次校验 hash 和范围，复用信息文件服务的字段校验、幂等保存与撤销历史。只读模式不提供修改建议工具。原始 PDF / Word、邮件、考学经历与系统文件不通过网页助手开放；募集要项原文提取继续使用专攻分析页面。

API 密钥只放在本地服务进程内存，不写入 SQLite、浏览器持久存储、对话日志或配置包；重启服务后重新填写。模型地址和非敏感设置、对话与建议保存在本机 SQLite。用户点发送后，对话及本轮工具读取的授权信息会发送到其配置的模型服务；没有内置平台模型密钥。

这版使用本地 Node.js 的函数工具调用编排，共用已有资料权限层，没有引入 LangChain 依赖。外部 Agent MCP 配置继续可用；网页端目前使用用户 API，尚未桥接本机 Codex 的登录与 App Server。后续可以增加该模型来源并复用对话与修改确认界面。

技术边界：数据库追加 migration 7（设置、对话、建议表）；最近 16 条对话进入模型上下文，旧对话仍保留在本机。每轮最多 8 次模型请求、20 次工具调用、5 项修改建议，每个模型请求最多输出 4096 token，总处理时间 3 分钟，同时最多 2 轮运行。工具结果限制大小；请求取消、中断、服务重启或 hash 冲突均有明确状态。没有通用 Shell、任意文件读写、自动发送邮件或模型直接保存资料的工具。

接口依据：[OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling)。本机 Codex 另一条路线依据：[Codex App Server](https://developers.openai.com/codex/app-server)。
