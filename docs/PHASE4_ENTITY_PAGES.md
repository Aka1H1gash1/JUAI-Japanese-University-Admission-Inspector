# 第四阶段：基础实体正式页面

第四阶段把大学、研究科、专攻、研究室和教师页面接入统一设计系统；专攻与研究室不再依赖 design=1，原查询参数兼容，既有实体 ID 和路由保持不变。

## 页面与业务

- 大学清单：紧凑卡片，校徽、名称、类型、地区和可核实的城市/行政区；不显示街道地址。缺失地址可只读参考已收录目录，不改写个人记录。搜索、排序、对比和导出保留。
- 大学：基本资料、官网、费用住宿与研究科入口。移除重复募集要项和招生文件总览，原数据不删除。
- 研究科：研究领域、专攻列表与已有经验入口；招生历史由专攻的折叠来源区访问。
- 专攻：一个招生信息主区，选择招生批次切换六项要求和关联文件；batch 查询参数保留刷新上下文。文件与过去问并列，研究室在最后。旧考试、通用要求和大学/研究科历史来源按需访问，不自动推断归属。
- 文件：复用 DocumentArchive 上传/预览/编辑/删除；其他相关文件合入文件区，不建立特殊文件模块。上传后关联打开管理区时的批次，批次变化或版本冲突明确提示，已保存文件仍保留。允许编辑下载文件名，格式不能改变，文档 ID、路径、原始字节与阅读笔记不变。引用阻止删除，解除后可以移入可恢复区。
- 研究室：介绍、方向、位置、成员构成和教师。原有说明保留；普通页不再复制专攻招生信息。材料/待办/补充要求通过抽屉及原 tab 深链接访问，日程开关用一次 timeline PATCH 保存，不反复切换想考状态。
- 教师：身份、研究方向和联系信息采用阅读布局；编辑、心仪、论文、邮件和联络经历仍可用。列表中的研究室关联可点击到同一普通详情。
- 目录：手动未匹配资料需要明确核对；AI 核对页可确认公共目录，目录标识仅用于新建。已有档案依旧 ID-only 关联，不补空、不覆盖。

## 数据兼容

无新增数据库 DDL，保持 schema18。研究室 description/location 使用现有可选扩展投影，服务端校验长度，旧客户端遗漏字段时保留。父级删除先在同一事务解除随该专攻删除的批次引用，再移除文件索引，原文件保留。历史批量同名未关联记录继续兼容，稳定目录身份的重复添加仍受阻止。

备份位于 ../git-backups/juai-1.0-phase4-20261115：一致性工作区副本、两个 Git bundle、SHA-256 清单；quick_check=ok。原有未跟踪目录及原始需求文件保留。

## 验收证据

- 核心76项、前端4文件14项、平台11项测试通过，类型检查、生产构建和提交 hooks 为交付门槛。
- 浏览器沿真实大学→研究科→专攻→研究室→教师路由访问，默认页面不需要预览参数。
- 六种页面均实测390px，无页面横向溢出；桌面1440px与深色截图位于 ../../juai-server/artifacts/juai-1.0-phase4/。
- 正式截图使用现有资料，保留123等原有命名，没有生成虚假大学资料。
- 增删改只在独立备份副本上验收：两个明确标记的批次切换科目、内诺与文件范围；选择B后刷新保留；上传自动关联B；文件标题与下载名保存；引用阻止删除，解除后删除成功，原有两份文件保留。
- 键盘操作日程开关仅发一次 PATCH 200，autoSync变false而wantApply仍true。研究室介绍/位置的旧客户端保留、父级删除及文件原始字节保护由集成测试验证。
- 部分自动化点击碰到隐藏选择节点或动画遮罩，使用可见选项及键盘复核；未将失败点击计为保存成功。

## 阶段边界

本阶段不部署生产、不调用付费AI、不发送邮件。修考申请工作台、材料ZIP、教授邮件AI工作区与全局剩余页面在第五、六阶段；最终同源部署在第七阶段。AI解析自动按结构化批次采纳仍属于后续业务接入，不因手动批次页面完成而标记全量完成。
