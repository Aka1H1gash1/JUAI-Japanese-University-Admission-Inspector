# JUAI 1.0 页面与交互准则

## 页面职责

- 列表用于发现、筛选和选择，不展示完整地址或整段招生要求。
- 大学/研究科用于认识机构与进入下级；专攻承载招生和文件；研究室承载方向/介绍/成员/教师；申请工作台承载个人材料与进度。
- 日历承载日程待办，申请总览不再复制待办；教授联络采用工作区/邮件双栏；普通研究室不代替申请工作台。
- 设置居中收窄。个人信息先阅读，动态语言编辑等待兼容模型。账号安全与个人学术档案职责分开。

## 内容规则

1. 每页主标题只有一个。主要动作不超过两个，其余归入上下文操作或编辑入口。
2. 普通详情不默认呈现输入框；短标签+正文、语义分组、日期和文件列表优先。表格只用于真正需要逐行比较的记录，不放长篇正文。
3. 一份信息一个主要展示位置，来源和历史按需展开。卡片表示主题，不逐字段包边。
4. 标题/关键值/正文/辅助值有层级；数字不替代含义，图表必须有可靠数据与文本替代。
5. 未确认、暂无数据、空集合和加载失败不同。没有可靠成员人数不画比例；内诺未知不当非必须。
6. 旧考试年份不冒充入学年度，批次选择不混合不同类别。共通要求显示范围待核对，保留原文/来源入口。
7. 长正文保留换行并 overflow-wrap:anywhere，Grid 子项 min-width:0；不截断必要招生内容。
8. 目录图片优先本地资源并保留完整署名许可，缺图使用已有建筑图标。

## 原型边界（第二阶段历史）

- `?design=1` 进入专攻/研究室代表原型，同路由同 ID 同 store；不维护第二份数据库或硬编码大学数据。
- 原型保留「返回现有页面/原版与申请工具」。历史、原件、任务和邮件不会因为布局隐藏而被删除。
- 选择旧考试记录只切换已经存在的记录；展示层没有批次能力时直说范围尚未结构化。未知内诺显示未确认，不放一个无效保存按钮。
- 文件预览/下载读取原 API；上传、编辑、删除打开已有归档组件。尚未实现的新业务只在开发进度记录，不显示可点击的伪功能。

## 交互与可访问性

键盘可到达链接、按钮、选择器；图标按钮有中文名称；focus-visible 清晰。标题按 h1/h2/h3 组织，select 关联 label，错误使用 alert、加载使用 status。手机关键按钮可触达，弹窗可滚动，关闭/取消可用。悬浮不能是唯一读取方式。

## 验收矩阵

每个代表页实测 1440×900、390×844；选择另一条现有记录检查内容同步；桌面深色和长文本检查；无页面横向溢出，文件长名/空数据正常；编辑取消不写入，失败保留草稿；原有编辑、归档、研究室及教师跳转可达。

截图只展示真实本地工作区，无数据就展示真实空状态。临时验收草稿不保存，不以测试数据伪装产品结果。迁移、ZIP、AI、配额、双邮箱验证不属于本阶段完成项。

## 第四阶段正式页面

专攻与研究室默认使用新布局，design=1 仅兼容旧链接，不再维护旧页面副本。原材料/待办 tab 链接打开对应工具抽屉。招生批次切换同时切换文件范围；未知范围的旧资料明确分开。大学和研究室普通详情不复制招生正文，历史与原件仍可从专攻来源区及原历史功能访问。
