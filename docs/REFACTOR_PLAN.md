# JUAI 1.0 合并实施计划

2026-11-15。两份需求为同一产品重构，不按文档拆项目。阶段1–2已完成，用户已授权并继续完成阶段3基础能力；当前未进入生产部署。

## 版本与范围

共享核心位于本仓库，当前基线 `04a0fe5ab`（包版本 1.4.2）；私有平台位于同级 `juai-server`，HEAD `ad0cc3b`，线上发布代码 `e49f05d`（Server 0.7.2）。历史核心版本与下一产品版本 1.0 属于不同命名，不在原型阶段提前变更发布版本。

保留现有路由与数据；代表性原型在实际页面中以 `?design=1` 显式启用，提供原版返回入口。个人档案已有阅读页继续收敛到设计系统。默认页面的全面替换在阶段 4–6 完成。

## 合并路线与阶段门槛

| 阶段 | 业务与设计共同产物 | 前置条件 / 验收 |
| --- | --- | --- |
| 1 审查与备份 | 路由、模型、API、样式、目录、未提交改动审查；一致性备份；分支；本计划 | 备份 quick_check、清单 hash、代码可恢复；独立 commit |
| 2 设计规范与代表原型 | Tokens、标题/分区/日期/文件/空状态组件；个人档案、专攻、研究室真实数据原型 | 阅读与编辑分离、响应式、业务缺口明示、浏览器截图、类型/Lint/构建、独立 commit |
| 3 基础数据与公共能力 | 目录标识、招生批次、内诺三态、成员人数、动态语言记录、文件引用/配额、账号安全迁移与 API | 先做兼容迁移及隔离测试，保留旧字段和人工修改；为页面建立可靠数据契约 |
| 4 基础实体页面 | 大学、研究科、专攻、研究室、教师与目录搜索 | 消费阶段 3 的真实能力；原型升级为正式默认布局；不重复招生信息 |
| 5 申请与 AI | 独立申请工作台、材料/ZIP、日历、教授邮件双栏与 3 类 AI、网址解析 | 复用文件/批次/目标关联；增删改持久化；AI 推测与教授承诺分开 |
| 6 全局统一 | 剩余列表、总览、账号、设置、导航 | 隐藏指定入口但保留能力；全局密度/主题/错误一致 |
| 7 测试和部署 | 全链路、迁移、隔离、文件、AI、可访问性、生产包和回滚 | 本地及服务器同一源码和固定构建；备份后部署，健康与业务验收 |

## 关键数据依赖与迁移方案（设计，尚未执行）

1. 当前 schema 14 为关系化核心，后续已有 15/16 迁移继续保留。公共目录目前静态资源，核心大学记录没有 catalogId/schoolCode；先检查服务端共享目录能力，再增加可空稳定引用，旧数据只有唯一可信匹配才回填，不明确留空供人工确认。许可元数据随目录保留。
2. 现有 `exam_records.year/session` 是考试年份/描述，不能当作完整入学批次。新增兼容的招生批次关系，带入学年度、批次、考试类别、适用范围和来源；迁移中不跨批次拼接。旧通用专攻要求作为未定范围资料保留，不伪称批次专用。`consentRequirement` 为 required/optional/unknown，旧值默认 unknown。
3. `foreignStudentStatus/Notes` 不含人数；增加 nullable 非负人数和来源，中国人数≤外国人数，缺任意可靠项不生成完整比例；禁止从 yes/no 推导人数。
4. 旧 profile.language 字符串保留；增加动态记录 id/type/result/date，转换失败原文继续可见，用户确认后才结构化。入学月份/预计毕业时间原型不从参考图代填。
5. 先复用 documents 与用户工作区物理目录，统一文件对象和业务引用，普通文件支持无专攻关联；配额由平台计算。申请材料完成状态与附件状态独立；引用删除前提示，不级联误删原文件。
6. 新申请目标将 lab、major、university、招生批次关联读取；目标自身管理进度、材料和邮件，不复制招生基础信息。旧 lab.tasks/contact 保留读兼容，幂等回填、版本校验、逐用户事务。
7. 每条迁移先备份，追加版本；在备份副本验证行数、文件 hash、外键、反复运行幂等、跨用户隔离、旧客户端读写。恢复需代码与匹配的数据备份，禁止只回退旧写入器破坏新关联。
