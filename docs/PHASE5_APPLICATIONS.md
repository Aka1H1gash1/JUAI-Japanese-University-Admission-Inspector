# 第五阶段：申请工作台、材料与邮件 AI

2026-11-16。开发分支 refactor/juai-1.0；尚未部署生产或发布正式1.0。

## 已实现

- 修考之路与联络看板进入独立 `/japan-grad/applications/labs/:labId` 工作台，普通研究室详情保留。申请目标关联研究室与招生批次，基础信息通过关联读取；目标和页签在地址中保留，刷新不会误切其他目标。
- 目标材料独立新增、编辑、删除、勾选完成；上传文件不会自动完成。材料/文件左右分栏，支持选择、拖拽上传、关联已有文件、阅读、下载、解除及删除。删除前检查其他引用并说明影响，实际存储复用 documents/content-store。
- 明确批次首次建立目标时按已保存要求生成模板；之后独立管理。重复生成按来源去重，不覆盖手动改名、完成状态或备注；长要求原文保留。无批次时只有明确核对适用范围后，才能按专攻通用要求生成，不推定年份。
- ZIP仅读取当前目标关联文件，按可读材料分类组织，中日文与重名文件编号保留扩展名；限制500文件/100MB。安全路径检查复用 safeFile，不包含其他目标未关联文件。
- 教授联络保留现有看板和阶段编辑；工作台左右展示业务和目标邮件。每个目标明确固定教师联络经历，可新建或关联，不把其他批次当前进度自动带入。更换经历只解除旧邮件的目标关联，原邮件保留。
- 邮件新增/编辑/删除及JSON导入导出复用原记录接口。导入必须明确日期、方向与地址，不猜测时间；重复记录不覆盖用户编辑。目标内新增/导入记录自动关联对应目标和经历；其他历史邮件需主动选择。
- 单封总结、目标进展总结、回复草稿使用用户配置的 API；回复需选择邮件和填写要求。进展要求区分明确事实、未解决问题与建议；草稿可修改、重新生成、复制，绝不发送。邮件上下文严格按目标/经历，回复仅同老师此前往来；停止、连接变更和退出会中止请求。
- 待办与日期管理集中到 `/calendar`；总览移除重复待办与完整日历，保留申请状态入口。工作台显示所选批次日期；原有时间线明确标为原有日程，不猜测历史归属。
- 网址解析中的自用API设置居中展示，隐藏本地Agent备选卡及方式编号；保留原底层Agent和高级配置。

## 数据与 API

追加迁移19，不修改1–18。新增 application_targets、application_materials、application_files、application_mail、application_contacts。旧想考研究室生成未指定批次目标，旧材料快照与现有联络经历关联保留，旧表不删除、不改写。修改材料使用version；目标联络关联使用目标version。

- GET/POST `/applications/labs/:labId`：列表和幂等建立目标。
- GET `/applications/:id`：目标、材料/文件、固定联络经历和明确关联邮件。
- POST/PUT/DELETE `/applications/:id/materials/:materialId?`：独立材料操作；PUT可关联本用户个人文件或同专攻文件。
- POST `/applications/:id/seed`：按批次生成；通用要求需要confirmCommon明确确认。
- GET `/applications/:id/zip`：严格按目标生成ZIP。
- POST `/applications/:id/contacts`：明确关联此研究室教师的经历，版本冲突拒绝。
- POST/DELETE `/applications/:id/mail/:messageId?`：只关联匹配目标经历的邮件。
- POST `/applications/:id/ai`：mail_summary / progress / reply；返回draft，不写入邮件或教授承诺。

平台沿用每用户独立工作区与密钥保险库，没有客户端指定用户ID的新增入口。文件引用查询、删除保护及父级删除事务同时支持目标材料。batch被目标引用时拒绝直接删除。
