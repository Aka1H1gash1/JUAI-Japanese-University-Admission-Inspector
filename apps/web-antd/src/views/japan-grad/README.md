# JapanGrad 本地浏览器工作台

当前流程：大学清单与横向对比 → 研究科 → 专攻 → 研究室 → 老师；专攻下管理募集要项、过去问和对应答案，老师下管理论文和邮件往来。

## 界面与主题

界面使用统一的字体、间距、圆角和语义配色。桌面侧边栏提供大学清单、修考之路、已有大学和当前研究科 / 专攻 / 研究室的快捷入口；手机通过顶部菜单打开导航。右上角主题菜单支持浅色、深色与跟随系统，选择保存在当前浏览器中。弹窗、抽屉、上传、考试表和邮件与页面共享主题。

点击侧边栏或页脚「本地工作区」可查看资料保存位置并复制路径。界面图标使用已安装的 Lucide 本地组件，无需访问 CDN；老师卡片使用姓名缩写作为身份标记。支持键盘跳转到主要内容，选择框提供内部输入标签与展开状态，并响应减少动态效果偏好。

设计审查、改版前后预览及 Lighthouse 报告见工作区 `design/REDESIGN.md`。所有设计验证数据都在独立的临时工作区中。

大学清单使用紧凑卡片，点击卡片任意普通区域进入大学详情，不再单独显示「查看研究科」按钮；对比勾选独立操作。老师卡片同样整卡进入独立详情页，心仪和编辑按钮独立操作。老师详情地址包含大学 / 研究科 / 专攻 / 研究室 / 老师 ID，旧老师链接继续可用，验证完整归属关系，支持刷新、直接打开、返回所属研究室；资料、论文库与邮件往来的当前栏目保存在 URL 查询参数中。

所有工作台页面顶部提供「返回上一级」，按大学 / 研究科 / 专攻 / 研究室 / 老师层级返回，直接打开链接也可用；修考之路返回大学清单，大学清单作为根页面禁用返回按钮。旧老师链接能识别所属研究室并返回。

## 研究室与修考之路

专攻详情以研究室为入口，每个研究室可记录名称、日文名称、研究方向、官网、个人备注，以及额外考试 / 出愿要求。整张卡片进入研究室详情，老师在研究室内单独维护；老师的论文与邮件仍属于原老师。编辑老师时可调整到同一专攻下的其他研究室，身份 ID、论文和邮件不变。

在「修考之路」点击「新增研究室」，可直接搜索所有已整理的研究室，按大学筛选并一次勾选多个加入；支持全选当前结果，已加入的目标明确标记且不可重复添加，取消选择窗口不修改资料，确认时一次保存整批选择。搜索或筛选切换不会丢失已选项。也可在研究室卡片或详情点击「想考」，目标会出现在侧边栏的「修考之路」。此处支持按研究室、大学、方向、地域、老师搜索，勾选 2–6 个目标横向对比。对比可选具体考试年份或各专攻最新已记录年份，同一年的不同批次分别显示。年度开销 = 年度学费 + 12 ×（月房租 + 月生活费），不含一次性入学金；首年和两年总费用另列。缺失费用显示已知小计与待补充项。

「导出 Excel」导出当前搜索结果，「导出所选」或对比窗口内的按钮只导出已选研究室。工作簿包含「研究室对比」「历年考试」「材料明细」「待办明细」「字段说明」，对比表包含研究方向、老师、QS / 榜单年份、地域 / 都道府县、年度 / 首年 / 两年费用、费用明细、寮信息、考试科目与各阶段时间、出愿材料、研究室特殊要求、官网、备注等。历年考试表包含导出目标所属专攻的所有记录，不受对比年份筛选影响。冻结表头与前两列，支持筛选、换行；费用输入为数值，费用合计为带缓存值的可重算公式，输入缺项时相应总费用留空。

研究室的考试与通用出愿信息引用所属专攻；额外考核、联系内诺或追加材料在研究室特殊说明中维护。变更所属专攻信息会同步更新该专攻下研究室的展示和之后的导出。

首次升级时将同一专攻、同一研究室名称的旧老师归组；未填研究室名称的老师暂归为「老师姓名研究室」，可重命名或调整归属。已有老师关注标记继续保留，不自动等同于研究室「想考」。升级事务在 `workspace_data_backups` 表保存原工作区 JSON 与修订号，升级失败时整体回滚；旧页面保存时遗漏研究室集合或老师关联，不会清空已有研究室及想考状态。

## 教授联络、日程与准备进度

教授联络看板按每位老师的当前考学经历展示卡片，分为未联系、已发首封、已回复、已约面试、已面试、已拿内诺、已结束七列。每列展示对应内容：研究方向 / 论文 / 要求、实际首封、来往信件、面试预约 / 准备、实际面试 / 问答复盘、内诺原文 / 签署文件、最终结果。研究室主要老师仍用于研究室摘要和横向对比，看板操作其他老师不会替换主要老师。

老师详情的「考学经历」和研究室入口共用一张经历记录，切换阶段仅改变展示，完整经历总表可查看所有阶段。草稿、回复要点、面试准备与问答、结果备注均可编辑；日期不凭状态自动填成当天。新建经历只需名称，原经历归档，邮件与内诺文件保持原归属；最多保留 20 段历史经历。未保存草稿仅在本次页面会话保留，刷新浏览器前请保存。

「邮件往来」支持指定归属经历。当前阶段在已约面试之前时，实际发信 / 来信自动更新首封 / 回复状态与来源日期；进入面试及后续阶段后不自动倒退。手动修改过的日期保留。内诺和结果可以选择本经历的实际来信作为原文，也可手动录入；删除或移走所引用邮件时保留当时正文。签署文件按经历上传并手动标记签署状态与日期，不代表电子签名认证。没有记录的真实邮件不会用草稿冒充。应用不发送邮件。

老师经历中的预约 / 实际面试、内诺和结果日期同步时间线；编辑来源节点可联动经历，新增个人节点需主动勾选联动。自定义标题与备注保留，历史经历的节点不会覆盖新经历。邮件归属与经历变更在服务端事务中保存，版本冲突保留输入并提示重新核对。数据库版本 5 为旧记录追加经历标识，不删除原邮件、论文或文件。

研究室详情将「材料」和「待办」拆为独立栏目。材料记录 0–100% 的准备进度；待办必须有日期并进入时间线。两个栏目均提供「智能导入」和「手动新增」；智能导入仅使用已核对的募集要项内容，不推测不完整日期。常用材料模板继续可用，重复项目不重复加入。每个研究室最多 200 项。

修考之路右侧按全部想考目标汇总材料完成比例、已建清单覆盖率、同名材料平均进度和未完成待办，并展示近期节点。其他待办不计入材料进度；没有建立材料清单的目标明确标记，不算作已完成。材料进度采用已建材料项的平均百分比，完成数量以 100% 为准。

时间线 / 甘特图汇总专攻的出愿窗口、所选考试年份的笔试 / 面试 / 结果日期、所有老师的计划联络 / 首封 / 跟进 / 面试 / 内诺、研究室待办截止日期。支持按起始月份显示 3、6、12 个月，点击节点查看来源；倒计时按日本时间刷新，提示 30 天内节点及逾期的未完成待办 / 联络计划。含年份的 YYYY-MM-DD、YYYY/M/D、YYYY年M月D日可识别，考试可使用完整日期范围；常规月份、未知日期等保留原文，不推测具体日期。

重叠提示区分同期出愿窗口和考试 / 教授面试同日安排。同一专攻共享的同一场考试去重；同日提示不等于时段冲突，需结合具体时间和地点确认。可导出当前时间范围的 `.ics` 日历，共享考试去重，保留研究室说明；未完成的未来节点附带提前一天提醒，出愿窗口另附截止前一天提醒，最后一天的倒计时显示「今天截止」。页面内提醒仅在工作台打开时展示，后台提醒由导入后的系统日历提供。

Excel 对比新增主要联系老师、联系状态、首封日期、教授面试、跟进与回复要点；额外的「材料明细」与「待办明细」分别导出逐项进度、日期和备注，不包含邮件草稿正文。旧页面遗漏这些扩展字段时服务端保留原值，编辑研究室或老师基本资料也不会清空；删除 / 调整主要老师归属时取消失效的主要联系关联。

## 本地运行与存储

浏览器只作为工作台界面。本地 Node.js 服务只监听 `127.0.0.1`，SQLite 保存业务数据，原始文件复制到独立工作区的真实文件夹。工作区默认位于 `~/Documents/JapanGradWorkspace`，可通过 `JAPANGRAD_WORKSPACE` 修改。

大学支持 QS 排名、榜单年份、所在地和国立 / 公立 / 国公立 / 私立类型。地域采用两级下拉：先选择北海道、东北、关东、中部、近畿、中国、四国、九州、冲绳之一，再选择对应都道府县，共覆盖 47 个。都道府县支持中文和日文搜索；更换或清空地域会清空不匹配的都道府县。城市 / 详细所在地仍可自由填写。旧所在地原文保留；能明确识别的中文、日文都道府县名称会在编辑时预选对应地域和都道府县，已主动清空的选择不再自动回填。清单、详情和对比同步展示，大学搜索也支持都道府县的中日文名称。旧类型和无法识别的旧地域原值保留，编辑时可重新选择。

国立、公立、国公立的入学金默认 282,000 日元（仅第一年一次），年度学费默认 535,800 日元，可按学校实际情况修改；私立费用手动填写。总费用另外包含每月房租 / 寮费、每月生活费（不含房租）；首年预算为入学金 + 年度学费 + 12 ×（月租 + 月生活费），两年预算只收一次入学金，其余按两年计算。费用支持零元和留空；存在空项时显示已知费用小计和待补充项，不将未知费用当零。恢复默认学费只影响入学金、年度学费，保留生活预算。旧大学缺少学费字段时按类型显示默认值，已保存的自定义金额或主动留空不会被覆盖。

大学资料可记录寮申请状态（待确认 / 可申请 / 不可申请）、申请官网和资格 / 住宿备注。此状态不会自动修改房租预算。

新增或编辑大学时支持上传、预览、更换和移除校徽（PNG、JPG、WebP，最大 3 MB），保存大学后生效。原图片保存在工作区的 `university-logos/`，SQLite 保存文件标识。图片按真实内容识别类型；取消编辑保留原大学校徽。更换或移除后原图片仍保留在工作区，完整备份时一并复制。

大学详情集中展示基础资料、寮信息、研究科 / 专攻 / 老师 / 心仪老师数量、研究领域、择校笔记和总预算；清单、详情与对比统一展示校徽，横向对比包含寮信息、住宿生活费与总预算。

支持 PDF、DOC、DOCX、MD、TXT，按年份归档。募集要项与过去问采用独立的卡片清单，点击卡片进入资料详情，支持个人备注；可直接从专攻读取原文、定位初步字段并核对 Agent 草稿。PDF 通过浏览器自带阅读器打开，MD/TXT 显示原始文本，DOC/DOCX 下载后用本机应用打开。过去问的答案必须关联同专攻、同年份的具体试题。

募集要项、过去问、老师论文统一通过「新增」按钮打开上传弹窗，可拖拽单个文件或点击选择。每次仅接受一个文件，批量拖入会提示重新选择；选中后显示文件名、大小，可更换或移除，标题自动使用文件名且不会覆盖手动填写的标题。点击保存才上传原文件，取消不会新增资料。支持上述五种格式，单个文件最多 50 MB；答案上传也复用同一选择界面并保留试题 / 年份关联。

专攻页面在考试表格上方独立展示「出愿信息」：出愿开始 / 截止时间段和所需材料。可点击「编辑出愿信息」维护，时间支持具体日期或每年的常规时段，材料按行填写并展示为清单；两端为标准日期时校验截止不早于开始。信息作为专攻的通用资料保存，编辑专攻或考试记录时保留，旧页面遗漏这些字段时也不会清空已有值。

专攻详情的「历年考试信息」采用对比表格，列为考试年份、考试科目、笔试时间、面试时间、结果发布时间、备注及操作；按年份倒序显示，同一年可记录多个批次。备注直接展示该年份的出愿时间、所需材料或其他特殊变更，来源链接和原考试时间也放在备注栏。支持单条新增、编辑、删除，时间可填写具体日期、时段或待公布。旧记录的原考试时间完整保留，可在编辑时整理到对应时间栏，未填写的新栏显示待填写。

「批量录入」支持逐行填写、按起止年份生成多行、从表格粘贴制表符分列的数据（可带表头）。每批最多 50 行，空白行忽略；相同年份和批次重复时提示处理，不覆盖已有记录，生成年份时跳过已有的未分批次年份。批量通过校验后使用一次工作区保存请求，任一行错误时整批不写入。记录保存在工作区数据库内，编辑专攻不覆盖考试记录；旧页面保存时缺少的新时间栏也会保留原值，主动清空则按用户修改保存。

批量表格也支持填写每年的备注。粘贴带表头数据时根据列名识别备注；无表头则依次为年份、科目、笔试、面试、结果发布时间、批次、备注，兼容此前第六列为批次的数据。

老师独立详情页包含资料、论文库、邮件往来三个 Tab。论文支持作者、会议/期刊、阅读笔记、预览和下载；邮件采用复制粘贴，支持收发方向、日期、下一步行动与跟进日期。

首次打开空工作区时会尝试导入同一浏览器地址下的旧 `japangrad-university-explorer-v1` 数据，保留原浏览器数据及 `-before-v2` 备份。正式数据以本地 SQLite 为准，其他浏览器也可打开同一工作区。

## 开发

需要 Node.js 24 和 pnpm。仓库根目录：

```sh
pnpm dev:japangrad
```

另一个终端进入 `apps/web-antd`：

```sh
../../node_modules/.bin/vite --host 127.0.0.1 --port 5666 --strictPort
```

打开 `http://127.0.0.1:5666/japan-grad/overview`。Vite 将 `/api/japangrad` 代理至本地服务 5667 端口。

## 构建和启动

```sh
pnpm build:japangrad
pnpm start:japangrad
```

生产工作台由同一个本地服务提供，首页地址为 `http://127.0.0.1:5667/japan-grad/overview`；根地址 `/` 和旧入口 `/japan-grad` 均进入申请总览，大学清单独立位于 `/japan-grad/universities`。资料阅读页位于 `/japan-grad/documents/:documentId`，PDF.js 引擎、worker、CMap 与字体均由本地服务提供，不使用在线 CDN。前端构建前需安装 `local-server` 的锁定依赖，类型声明与运行时使用相同 PDF.js 版本。

阅读服务：`local-server/document-reader-service.mjs`，迁移 8 新增阅读位置、笔记与版本化文字缓存。PDF 高亮保存 PDF 坐标，文字引用保留页码 / 原文 / 上下文。笔记单条修订校验，原文件 hash 变化时旧笔记仍保留但不套用高亮。文档删除通过外键同时清理关联记录。

## 打包

提供经官方 SHA256 校验的 Node.js 24 macOS arm64 运行时目录，执行：

```sh
NODE_RUNTIME_DIR=/path/to/node-v24.x-darwin-arm64 pnpm package:japangrad
```

产物位于工作区 `releases/JapanGrad-macOS-arm64`。软件内含运行时和静态页面，双击 `启动 JapanGrad.command` 打开浏览器，无需安装开发环境。详见 `local-server/USER_GUIDE.md`。

## 视觉主题

统一靛蓝强调色与蓝灰中性色，浅色 / 深色使用语义变量。基础布局在 `style.css`，展示层在 `visual.css`，Ant Design Vue 的控件主题在 `layout.vue`。首页真实概览和预算复用已有工作区数据；无额外外部字体、装饰图或新组件库依赖。设计判断见 `design/VISUAL-REFRESH-2026-10.md`。

## 本地 Agent 信息文件接入

在「修考之路 → Agent 工作区接入」选择授权专攻与信息文件权限。可以选择只读、读取并编辑，或保留原来的仅募集要项分析权限。编辑时逐项授权专攻、研究室、老师基本资料、大学和研究科；大学 / 研究科为共享资料，默认不授权编辑。

创建后可复制 / 下载通用 MCP JSON 或 Codex TOML，也可下载完整配置 ZIP，包含两种配置、AGENTS.md、使用说明、授权范围和忽略令牌配置的 .gitignore。在独立文件夹中打开本地 Agent，将所需配置合并到客户端 MCP 设置后重新加载；保持 JUAI 服务运行。无需把源码目录交给 Agent。此轮不自动修改用户的客户端全局配置。令牌只在创建窗口返回，服务端只保存 hash；遗失时撤销并重新创建。旧连接不会自动获得信息文件权限。

建议对 Agent 说：“先查看 JUAI 连接状态和授权范围，列出可编辑的信息文件，再按我的要求更新资料。保存前说明字段变化，缺失信息不要猜测。”

| MCP 工具 | 用途 |
| --- | --- |
| get_connection_status | 确认服务连接与权限，不返回令牌 |
| get_information_workspace | 读取授权、字段 JSON Schema、地域选项和操作规则 |
| list_information_files | 搜索 / 分页列出逻辑 JSON 文件与可写状态 |
| read_information_file | 读取开放字段、父级路径及当前 SHA256 |
| write_information_file | 按原 hash 保存信息并同步工作区；提供唯一 requestKey 和摘要 |
| list_information_changes | 读取本连接最近 50 项修改摘要 |

信息文件路径如 `majors/<id>.json`、`labs/<id>.json`，由服务映射到 SQLite 中的现有记录，不是磁盘文件路径。内容使用 `{schemaVersion:1, kind, id, data:{...}}`，ID 和所属关系不可变；`data` 中未提供的字段保留，字符串可用空字符串清空。费用按整数日元字符串记录，材料和考试数组按工具返回的 Schema 填写。新建 / 删除实体、关系调整、邮件与考学经历、上传原文件、代码及数据库不通过这些信息工具开放。工具授权只限制 JUAI MCP 能力，不限制 Agent 客户端自身已有的 Shell / 系统文件权限。

写入重新检查令牌、专攻范围和资料类型；路径仅接受预定义逻辑路径，不访问任意磁盘路径。全工作区校验、资料变更与历史写入在本机服务事务中完成；hash 冲突要求重读合并，同一个 requestKey 重试不会再次应用。升级新增数据库 migration 6，保存 Agent 信息修改历史。

在接入窗口底部查看修改前后对照、刷新连接最近使用时间，或撤销单项修改。撤销仅恢复该项改变的字段，保留其他资料；字段之后有新变化时拒绝撤销，原记录仍可查看。普通页面约每 15 秒及重新聚焦时检查新修订；打开编辑弹窗时暂停自动更新，保存冲突不会静默覆盖 Agent 改动。

募集要项分析仍使用原有提取、证据与待核对草稿流程。信息编辑用于用户明确要求的资料维护，不替代来源核对。

## 网页 AI 资料助手（自带 API）

右上角「AI 助手」直接打开网页对话框。首次点击「模型与权限」，填写自己的 API Base URL、模型 ID、密钥，选择接口与授权专攻；保存后即可对话。每个对话固定自己的模型地址与资料范围，改设置会开始新对话。可以恢复历史对话、停止当前回答、删除对话，或打开「修改记录」对照与撤销已经保存的资料。

支持 OpenAI Responses 与 OpenAI 兼容 Chat Completions；本机模型服务可使用 localhost / 127.0.0.1 HTTP，远程 API 使用 HTTPS。模型必须支持函数工具调用，兼容性取决于服务商与模型；较新的 OpenAI 模型使用 Responses。默认流式显示，可在设置关闭流式以适配其他服务。Base URL 自动补充对应接口路径，不接受 URL 中的密钥参数。

助手可以搜索 / 读取授权专攻及所属大学、研究室、老师基本资料，查看已核对的补充报考要求，并提出资料修改建议。所有写入先显示修改前与建议值；点击「确认修改」后才保存。确认前再次校验 hash 和范围，复用信息文件服务的字段校验、幂等保存与撤销历史。只读模式不提供修改建议工具。原始 PDF / Word、邮件、考学经历与系统文件不通过网页助手开放；募集要项原文提取继续使用专攻分析页面。

API 密钥只放在本地服务进程内存，不写入 SQLite、浏览器持久存储、对话日志或配置包；重启服务后重新填写。模型地址和非敏感设置、对话与建议保存在本机 SQLite。用户点发送后，对话及本轮工具读取的授权信息会发送到其配置的模型服务；没有内置平台模型密钥。

这版使用本地 Node.js 的函数工具调用编排，共用已有资料权限层，没有引入 LangChain 依赖。外部 Agent MCP 配置继续可用；网页端目前使用用户 API，尚未桥接本机 Codex 的登录与 App Server。后续可以增加该模型来源并复用对话与修改确认界面。

技术边界：数据库追加 migration 7（设置、对话、建议表）；最近 16 条对话进入模型上下文，旧对话仍保留在本机。每轮最多 8 次模型请求、20 次工具调用、5 项修改建议，每个模型请求最多输出 4096 token，总处理时间 3 分钟，同时最多 2 轮运行。工具结果限制大小；请求取消、中断、服务重启或 hash 冲突均有明确状态。没有通用 Shell、任意文件读写、自动发送邮件或模型直接保存资料的工具。

接口依据：[OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling)。本机 Codex 另一条路线依据：[Codex App Server](https://developers.openai.com/codex/app-server)。

## 本机 Codex 与并排助手侧栏（2026-10-15）

右上角「AI 助手」现在展开固定在右侧的工作面板，主页面同时缩窄并重新排版。拖动两栏分隔线调整宽度，双击恢复默认；键盘左右键也可调整，宽度记在本机浏览器。收起后主页面恢复；较窄窗口使用全宽助手视图。资料与对话可以并排查看。

点击「连接本机 Codex」，自动检测 Codex CLI、沿用已有登录 / 模型配置，并创建 JUAI 专用网页会话。无需填写 API 密钥或手动安装 MCP 配置。模型列表由本机 Codex 返回，不硬编码；在设置中可选择模型、专攻和资料范围，自动检测失败时可填写程序绝对路径。未登录时提供官方登录入口。

也可点击「复制指令给本机 Agent」，让本机 Agent 只调用 JUAI 的连接接口完成这项连接。网页检测到新会话后载入。此指令帮助连接 Codex，不会让任意外部 Agent 自动变成网页聊天引擎，也不导入 IDE 现有聊天记录。其他 Agent 要直接在网页回复仍需实现其对话适配器。

实现使用 Codex App Server 的 JSONL / STDIO、初始化、账户状态、模型列表、临时线程、流式消息和动态资料工具。每轮创建独立临时线程，JUAI 自己保存聊天历史并提供最近上下文。程序在独立临时目录运行，采用随机名称的只读文件权限配置，命令、代码执行、外部应用、hooks、其他 MCP 与插件在该接入会话中关闭；权限未正确采用时拒绝启动推理。不修改用户的 Codex 全局配置，不读取或复制账户令牌。登录、模型服务与额度由本机 Codex 的配置负责。

本机 Codex 复用网页助手的资料范围、读取后才能提议、字段校验、人工确认、冲突保护和撤销记录。取消或退出会中断 Codex turn；停止本地服务同时关闭它所启动的 Codex 子进程。用户自己的 API 模式继续可选。

无需新增数据库迁移，模型来源保存在原设置 / 会话 JSON 扩展字段中。接入依赖 Codex 的实验性动态工具与权限接口，旧版本或管理策略不兼容时会显示错误并停止，不放宽权限。

依据：[Codex App Server](https://developers.openai.com/codex/app-server)、[Codex Permissions](https://learn.chatgpt.com/docs/permissions)。本机实际连接初始化已读取到已有登录与可用模型，并核对选中的只读权限；未启动模型推理。代码检查包括 Vue 类型、Vite 构建、Node 语法及 diff；未运行自动化测试。
